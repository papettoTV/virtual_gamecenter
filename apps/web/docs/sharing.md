# ライブとプレイ結果の共有設計

## 目的

観戦への招待と、終了したプレイ成果の共有を分ける。操作中の投稿要求や自動のSNS起動は行わず、開始前・休憩中・結果表示・観戦中に利用者が共有を選べるようにする。

## 共通機能とゲーム固有機能

共通機能は `src/features/sharing/` に置く。

- `share-service.ts`: ライブ状態、共有メニュー、観戦URL・結果URLの生成。
- `result-sharing.ts`: 結果ドラフト、明示的な共有時の保存、同時要求の統合、次プレイへの切替。
- `ShareActions.tsx`: 投稿文編集、投稿先選択、コピー、結果画像保存、共有結果ページ用カード。
- `result-presenters.ts`: ゲーム別のプレゼンター登録。ゲームルール・ゲームランタイムは読み込まない。
- `result-images.ts`: 保存・端末共有用のゲーム固有画像レンダラー登録。描画コードは必要時だけ読み込む。
- `sharing-events.ts`: 操作と流入・プレイ転換の計測。

結果投稿の内容はゲームごとの `sharing.ts` が返す `ResultPresentation` で変えられる。

| ゲーム | プレゼンター | 主役となる成果 |
| --- | --- | --- |
| BUZZ BARRIER | `games/graze-duel/sharing.ts` | クリア、スコア、時間、ボス撃破数 |
| 深海サルベージ | `games/deep-sea-salvage/sharing.ts` | 最大深度、そのプレイの調査種数、調査達成 |
| DOT WAVE | `games/dot-wave/sharing.ts` | CPU戦・対人戦、勝敗、ターン数、残りHP |

プレゼンターからタイトル、見出し、詳細行、投稿文、アクセント色、OGP画像用の英数字行を返す。画面カード・保存用PNG・サーバー側OGPは同じプレゼンターを使う。投稿文は共有メニュー内で編集可能。

新しいゲームを追加するときはプレゼンターを登録し、結果ドラフトの `metrics` に必要な項目を入れ、Workerの `METRIC_RULES` にその型を登録する。ゲーム固有の成果項目を共通スコア項目へ無理に変換しない。

画像は共通カードを基本に、ゲーム別レンダラーで全体を差し替えられる。深海サルベージの保存・端末共有画像は、保存した種IDと既存の魚アイコンを使う専用の図鑑カードとする。ゲームの状態がリセットされた後や結果ページからの再共有でも、終了時の図鑑を再現する。

## URLと保存

- 観戦URL: `/cabinets/{cabinetId}?game={gameId}&watch=1`。共有時は流入計測用の `shareId` を追加。
- 結果URL: `/results/{resultId}`。終了時の数値・公開表示名・ゲームバージョンを固定する。
- 結果API: `POST /api/results`、`GET /api/results/{resultId}`。
- OGP結果画像: `/results/{resultId}/image.png`。
- OGP観戦画像: `/share/live/{gameId}/image.png`。

ランキング登録とは独立して共有できる。結果は共有ボタンを選んだ時点で公開保存し、所有者の名前はサーバー側のプロフィールから取得する。公開APIに所有者ID・Cookie・メールを返さない。結果ページの閲覧者は、所有者としてPOSTせず既存URLを再共有する。

同じ結果UUIDの保存再試行は冪等。同じUUIDを別の内容・別の所有者で保存しようとすると409を返す。リトライ・新規プレイ・継続後の新しい終了時には、新しいUUIDを使う。保存済み結果は更新しない。

結果はクライアント報告に基づく記録であり、サーバーによるゲーム内容の完全な検証済み記録ではない。リプレイ映像は提供しない。自己ベスト、初クリア、順位、逆転など、判定基盤のない成果は文章に加えない。

## 表示タイミングと安全性

- 開始確認: 共有アイコンを控えめに表示。まだ始まっていないことが分かる文章を使う。
- READY・一時停止: 「観戦に招待」を表示。
- プレイ中: 共有アイコンを残すが、自動の促しは行わない。ソロプレイは手動共有時に停止し、自動再開しない。
- DOT WAVEの進行中のオンライン対戦: 一方の投稿操作で試合を止めないため、プレイヤーのライブ共有を無効化。観客は共有可能。
- 結果: 終了演出後の既存結果画面に「結果を共有」。ランキング登録後も同じボタンを使う。
- 結果ページ: 誰でも再共有でき、「自分も挑戦」「開催中のライブ・他のゲームを見る」へ進める。
- 共有メニュー: 手動操作でのみ開く。閉じる・Escape・Tab移動に対応。編集時のキー入力をゲーム操作へ渡さない。

ブラウザ側の保存画像は日本語の成果・表示名・日付を含むPNG。OGPはWorkerで生成する英数字のPNG。SNS共有先はFacebookとXのみとし、端末共有・LINE・Blueskyのボタンは表示しない。コピーと結果画像保存は補助操作として残す。

- X: Web Intentへ編集した文章と共有URLを渡し、利用者が投稿画面で確認・投稿する。
- Facebook: sharerへURLを渡す。投稿本文は自動入力せず、必要なら利用者が文章をコピーして貼り付ける。
- 共有メニューにFacebook／Xの切替式「投稿イメージ」を表示する。画像・タイトル・説明はこのアプリが提供するOGPデータに合わせ、投稿文編集も反映する。Facebookは本文を貼り付けた場合の参考表示であることを明記する。
- 投稿イメージはSNSの実画面ではなく、SNS側のカード表示・レイアウト・キャッシュを保証しない。ローカルURLやBasic認証で限定公開中のURLはSNS側から読めない場合がある。
- 画像を直接添付したい場合は保存したPNGを利用者が添付する。

## 限定公開との関係

結果のGET・結果PNG・ライブ用の静的PNGは公開読取ルート。結果ページにはJavaScriptなしでも成果を読めるHTMLを含める。結果保存は既存セッションと同一Originを確認する。

既存のサイト全体のBasic認証は解除しない。限定公開中、観戦ページとアプリ資産には引き続き認証が必要なため、SNSクローラーがライブのOGPを取得できない場合がある。一般公開の認証方針を決めた後に、本番の各SNSでカード表示・遷移を確認する。

## 計測

`sharing_events` に以下のイベントを記録する。投稿文や利用者IDは保存しない。

| イベント | 意味 |
| --- | --- |
| `share_opened` | 手動で共有メニューを開いた |
| `share_link_copied` | 文章とURLのコピーが完了した |
| `share_target_opened` | Facebook・Xの投稿先を開いた |
| `share_native_handoff` | 過去バージョンの端末共有APIが完了した。現在のUIでは送信しない |
| `share_image_saved` | 結果画像のダウンロード操作をした |
| `result_viewed` | 結果ページを閲覧した。同じタブ・結果・共有IDでは重複を抑制 |
| `play_started_from_result` | 結果閲覧から24時間以内に同じゲームを開始した |

観戦開始と観戦からのプレイ転換は既存の `live_engagement_events` を継続利用する。共有メニューの操作とSNS投稿完了は同一ではない。実際の公開投稿完了数は取得しない。

過去のクライアントとの互換性のため、計測APIは従来の共有先チャンネルも受け付ける。現在のSNSボタンはFacebook・Xの2種類だけである。

評価は「共有メニュー利用→共有URLへの流入→観戦・結果閲覧→プレイ開始」の転換を、ライブと結果、ゲームごとに比較する。計測APIはクライアント報告であり、不正耐性のある会計・報酬判断には使わない。

## ローカル検証と本番反映

- ローカルDBへ `0016_shared_results.sql` と `0017_sharing_events.sql` を適用する。
- テスト、型チェック、ビルドを実行し、実機で共有メニュー・投稿文編集・結果直リンク・再共有を確認する。
- 本番反映時は新しいマイグレーションとコードを整合させる。デプロイは利用者からの指示があるまで行わない。
- 本番SNSへの投稿、カードキャッシュ・プレビューの実確認は本番URLで別途実施する。
