# DOT WAVE 通信対戦

## 利用の流れ

1. ゲーム一覧からDOT WAVEを選び、自分の筐体を作る。CPU戦の開始に1クレジット。
2. 「観戦URLを共有」で `/cabinets/{id}?game=dot-wave&watch=1` を渡す。受け取った人は観戦から入り、空席でも自動的にはプレイヤーにならない。
3. 観戦中の「1クレジットで対戦」で予約。元のプレイヤーが承認すると消費する。拒否・キャンセル・承認前の退出では予約を解除する。既存の最大5人の申込待ちも利用する。
4. 両者の準備後、共通の開始時刻でエネルギー100・レベル1から開始。元のプレイヤーがシアン、挑戦者がピンク。CPUの自動操作は止まる。
5. 自分のキャラ側に手・点滅・リズムバーの枠・攻撃／防御カウントダウンを表示する。両者ともSpace / F / 自分のタップボタンで操作する。
6. FINAL WAVEまたはエネルギー0で決着。結果を確認して「この席で続ける／観戦に戻る」を押すと勝者がプレイヤー、敗者が観戦者になる。勝者は追加消費なしでCPU戦を開始できる。引き分けは元のプレイヤーが残る。

通信中は一時停止できない。通信切断・退出は切断した側の負け。再接続は新しい参加として扱い、失われた対戦への復帰は行わない。
新規プレイ／挑戦のクレジット不足時はプロフィールの「クレジットを追加」から既存の初回特典・購入画面を開く。課金額・消費処理は既存プラットフォームAPIを使用する。

## 同期

- 既存のCabinetRoomの観戦、対戦申込、承認、Ready、勝者への席移動を利用する。
- 現在の筐体プレイヤーのブラウザを共有アリーナの進行・判定の基準にする。状態は約80ms間隔で観戦者と挑戦者へ配信する。結果の提出はそのプレイヤーだけが可能。
- 各端末は往復通信からサーバーとの時計差を推定し、AudioContextを共通の拍に合わせる。挑戦者は手元で即時の入力演出を出し、基準側の判定で確定する。
- 挑戦者の入力は対戦ID・攻防番号・連番で識別。重複・過去の攻防・大幅な未来時刻を拒否する。受信遅延は最大300msまで許容し、リズム自体の判定幅は広げない。攻防の結果確定を300ms待つが、音声の拍時計は止めない。
- 観戦者は参加者の入力経路へ送信できない。クレジットはWebSocket接続のプレイヤーIDと筐体・ゲーム・用途を照合し、使用済み予約の再利用を拒否する。
- ブラウザを基準にした試作方式のため、ホストの停止・大きな通信遅延には影響を受ける。競技向けの完全なサーバー判定・不正防止は未実装。

## 開発・確認

ローカルDBに `0014_add_dot_wave.sql` を適用する。公開環境へ反映するときも同じマイグレーションが必要。
`tests/worker/dot-wave-room.test.ts` は独立したテストDBでクレジット、観戦、申込、承認、権限、席移動を確認する。
`tests/games/dot-wave-network.test.ts` は時計補正、入力の遅延・重複制限、ピンク側のカウントダウンを確認する。
