# ゲームバージョン

各ゲームを独立した `メジャー.マイナー.パッチ` の形式で管理し、画面右下に小さく `v1.0.0` の形式で表示します。初期値は全ゲーム `1.0.0` です。以前の開発用バージョンとの大小関係を意味しません。無料ベータであることは、サービス側の無料ベータ表示で別途案内します。

更新PRでは、ゲームを変更したときだけ対象の更新種類を明示して実行します。省略や未知の種類はエラーになり、番号は変わりません。

```sh
node apps/web/scripts/bump-game-version.mjs buzz-barrier patch
node apps/web/scripts/bump-game-version.mjs dot-wave minor
node apps/web/scripts/bump-game-version.mjs deep-sea-salvage major
```

| 更新種類 | 判断の目安 | 例 |
|---|---|---|
| major | 大幅なルール・ゲーム体験の変更 | 1.2.3 → 2.0.0 |
| minor | 新しいステージ・機能・要素の追加 | 1.2.3 → 1.3.0 |
| patch | 不具合修正・小さな表示やバランス調整 | 1.2.3 → 1.2.4 |

PR本文に対象ゲーム、更新前後の番号、更新種類と理由を記載します。複数ゲームならそれぞれ判断します。同じPRの追加修正やテスト再実行では増やしません。major更新時はminor・patchを0に、minor更新時はpatchを0に戻します。

番号はコミットに含めます。実行時刻・ビルド回数・デプロイ回数では変えません。並行PRはマージ前に最新developと照合し、その番号を基準に更新種類を再適用して番号の重複を解消します。

データの正本は `src/domain/game-versions.json` です。`GameDefinition.currentVersion` は同じ文字列を既存のAPI・プレイ結果へ渡します。過去の結果の旧バージョンは変更せず、新規結果だけ新しい番号になります。ランキングの区切りや過去データの移行は行いません。

ゲーム領域の隅の表示はプレイと観戦に共通です。クリックを受けず、スマホの全画面表示にも残ります。BUZZ BARRIERとDOT WAVEは右下、深海サルベージは図鑑ボタンと重ならない左下に表示します。DOT WAVEは専用のゲーム盤面に、それ以外は共通ゲーム枠に表示します。
