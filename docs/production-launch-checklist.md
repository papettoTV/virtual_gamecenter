# PULBASE 本番運用開始チェックリスト

作成日: 2026-10-10

最終更新日: 2026-10-13

対象: 日本向けの無料クレジット制ベータ。有料販売は人気・継続利用の手応えが出るまで保留する。

ゲーム・観戦・ユーザー登録・クレジットの既存基盤を前提に、無料ベータ公開までの残作業と完了条件を管理する。フリープレイにはせず、1プレイごとのクレジット消費による緊張感を維持する。有料化の詳細タスクは削除せず、再開できるように残す。

## 無料ベータの確定方針

- 新規クレジット購入を停止する。UIだけでなく、サーバー側でもCheckout作成を拒否する。
- 初回の無料5枚・ユーザー登録特典5枚を維持する。どちらも既存の一度限りの付与とする。
- 初回特典を受け取った端末または無料付与履歴のあるプレイヤーは、日本時間の暦日ごとに1回、残高が3枚未満なら不足分を無料で補充する。
- 0枚なら3枚、1枚なら2枚、2枚なら1枚を追加する。3枚以上を減らしたり、毎日一律3枚を加算したりしない。
- 判定する残高は無料・購入分を合わせた未消費残高。仮確保中の枚数は消費済みと見なさない。
- 補充は再訪問・残高確認・プレイ仮確保前に判定する。最初に実際の補充をした日を利用済みとして記録し、同日中の再読み込み・プレイ・ログアウトで繰り返し配布しない。
- 初回5枚を受け取る前の新規ゲストには、日次補充分を先に配布しない。初回5枚を消費した後は、初日でも未使用の日次補充を利用できる。
- 補充済みで残高がなくなった場合は、購入に誘導せず翌日の補充を案内する。ユーザー登録がまだなら登録特典の選択肢は維持する。
- 未訪問日の補充は貯まらない。アンケート・招待ボーナスは今回の対象外とし、後から検討する。
- 既存残高は維持する。以前作成した決済の確認・Webhook処理は消さず、新しい購入だけを停止する。

1. 購入を停止し、無料クレジットの日次補充を整える。
2. 無料ベータ向けの利用条件・プライバシー・問い合わせ窓口を整える。
3. 公開設定・安全性・監視・復旧を確認する。
4. 実機検証後、小規模な無料ベータを公開する。
5. 観戦流入・共有・再訪問・継続プレイを見ながら改善する。
6. 手応えが出てから、有料化の法務・決済・運営準備を再開する。

- 状態は「未着手」「対応中」「確認待ち」「完了」「保留」「対象外」を使用する。「保留」は有料化など再開条件を持つ作業に使用する。
- 完了条件を満たしたら、状態・担当・証跡を更新する。実装済みだけでは、本番設定や運用確認まで完了した扱いにしない。
- 証跡には関連資料、コミット、テスト結果、管理画面の確認日などを記載する。秘密鍵・個人情報は記載しない。
- 対象外にする場合は理由を残す。未解決事項を受容する場合は、判断者と判断日を記録する。
- 各段階の公開判定時には、対象リビジョン・環境・確認日を記録する。
- 初期状態の「未着手」は、このチェックリスト上の残作業を示す。既存の実装がないことを意味しない。

## 公開判定のチェック

### 無料限定ベータ

- [ ] 運営ルール、無料公開に必要な規約・プライバシー・権利確認が整っている。
- [ ] セキュリティ、監視、復元、問い合わせ対応を確認した。
- [ ] 主要フローを実機で確認し、重大な不具合がない。
- [ ] 新規購入がUI・APIの両方で停止しており、未完成機能を利用者が誤って選択できない。
- [ ] 初回5枚・登録5枚・1日1回の3枚までの補充と、1プレイごとの消費を本番で確認した。
- [ ] 同日の繰り返し付与を防ぎ、残高不足時は翌日補充を案内する。
- [ ] 残課題・担当・公開範囲を記録した。

### 有料購入公開

- [ ] 無料限定ベータの結果を評価した。
- [ ] 有料クレジットの法的整理、規約、特商法表記、購入表示を確認した。
- [ ] 本番決済設定とテスト環境での異常系検証が完了した。
- [ ] 付与漏れ、返金、ゲスト復旧、問い合わせ照合に対応できる。
- [ ] 残課題・担当・公開範囲を記録した。
