# 無料ベータの公開範囲と実機確認計画

更新日：2026-10-21

初回は日本国内の招待制10名、PCでのソロプレイとPC・スマートフォンでの観戦を対象とする。2026-10-21に運営者がこの範囲案と、検証環境のPC確認から進める順序を承認した。スマートフォンのプレイは招待者の協力による試験扱いとし、ゲーム別の実機確認後に対応範囲を広げる。範囲案の承認は公開許可・対応保証ではなく、招待経路・案内時間帯などの運用条件は未確定。長時間負荷試験は保留・未合格を維持する。

## 1 公開対象と人数

| 項目 | 初回の推奨案 | 条件・理由 |
| --- | --- | --- |
| 形式 | 招待制のクローズド無料ベータ | 不特定多数への一般告知、広告、公開SNSでの参加者募集はまだ行わない |
| 対象 | 日本国内・日本語で不具合を連絡できる18歳以上 | 最初は運営者の知人・協力者。ゲーセン経験者だけでなく初見の人も含め、操作説明の理解も確認する。未成年の利用条件は別途整備する |
| 招待人数 | 最初の5名で主要導線を確認後、合計10名まで | 登録者数ではなく協力者数。ゲスト利用も認め、ログインを参加条件にしない |
| 利用の目安 | 同時6人以内、うちプレイヤー2人・観戦者4人程度 | 招待時刻を分ける運用上の目安。サーバーにこの上限を強制する仕組みは未実装。長時間の安定性・収容能力を実証した数値ではない |
| 振り返り | 招待開始から7日後 | 不具合、開始・観戦体験、共有、再訪、問い合わせ、利用量を確認。日数経過だけで一般公開・増員しない |
| 料金 | 購入停止、初回受取5枚・初回登録5枚・日次3枚までの補充 | 無料ベータでも1プレイごとのクレジット消費は維持する。無料枠でインフラ費が必ず収まる保証はしない |
| 運営 | 初回利用は運営者が確認できる時間帯を案内 | 時間帯・連絡担当・対応目安を招待前に確定する。24時間の有人対応は約束しない |

招待URLや観戦URLは再共有され得る。招待制という案内だけではアクセス制御にならないため、実施前に「招待者だけがアクセスできる経路」と「想定外の流入を止める手順」を確認する。既存の検証用Basic認証を本番の参加者管理へ無条件に流用したり、管理用資格情報を配布したりしない。

10名・同時6人は安全を保証する試験結果ではなく、問題発生時に連絡・切り分けできる規模としての提案。既存の短時間24接続検証は通信配送の確認であり、実ゲームの描画・スマートフォン操作・継続稼働を保証しない。30分試験の未解決事項を残したまま人数を拡大する場合は、別途判断を記録する。

## 2 公開する体験

| 対象 | 初回の公開案 | 公開前条件 |
| --- | --- | --- |
| BUZZ BARRIER、DOT WAVE、深海サルベージ | PCのソロプレイ、ライブ観戦、任意のランキング登録・共有 | ゲームごとに開始・操作・終了・再挑戦を実機で確認。合格したゲームだけ公開する |
| スマートフォン | 観戦を優先。プレイは試験対応と明示 | 観戦UI・スクロール・音声・共有を実機確認。プレイはゲームごとにタッチ操作まで合格した端末だけ対応候補へ昇格 |
| 対戦・協力 | 初回の一般提供から外す | 課金・承諾・切断・再戦・初心者保護の確認が別途必要。非公開モードはUIだけでなく直接要求からも開始できないことを確認する。現状で制御できなければ公開前の実装課題 |
| Google登録 | 任意で利用可能 | ゲストでプレイ・観戦できること、登録特典の一度限り付与、復帰先・再ログインを確認 |
| SNS共有 | 招待範囲内の観戦URL・結果URL共有 | シェアボタンから公開SNSへの投稿は可能なため、非公開募集の案内と機能上のアクセス境界を区別する。参加資格外の人へ見せる範囲も決める |
| 購入、チャット、リプレイ、新ゲーム追加 | 初回の対象外 | 購入停止を維持。未提供の機能やゲームを利用可能と案内しない |

対戦を隠すだけでサーバー側を開けたまま、スマートフォンを未確認のまま「対応」と掲載する、といった状態で公開しない。この資料では機能制限・参加者管理の実装や本番デプロイは行わない。

## 3 対応端末の案

| 端末・ブラウザ | 初回の対応候補 | 実機確認の最低構成 |
| --- | --- | --- |
| Windows PC / Chrome | ソロプレイ・観戦 | 実際のWindows PC 1台、キーボード・音声あり。現行安定版の実バージョンを記録 |
| Mac / Chrome | ソロプレイ・観戦 | Mac 1台、キーボード・音声あり。過去のChrome確認に加え、公開候補リビジョンで再確認 |
| iPhone / Safari | 観戦。プレイは試験対応 | 実機1台、縦画面優先・横向き復帰も確認。OS・ブラウザ・機種を記録 |
| Android / Chrome | 観戦。プレイは試験対応 | 実機1台、縦画面優先・戻る操作も確認。OS・ブラウザ・機種を記録 |
| iPad、他ブラウザ、SNS内ブラウザ、旧端末 | 初回の対応保証外 | SNS内ブラウザは通常ブラウザで開く案内を用意。拒否・クラッシュしてよいという意味ではない |

Windows等の必要実機が確保できなければ、未確認を合格にせず初回の対応範囲を狭める。具体的な最低OS・最低スペックは今の証跡だけでは決めない。エミュレーター・PCの画面幅変更は補助であり、実機の音声・タッチ・発熱確認の代替にしない。

## 4 公開前の実機確認

未実施のチェック表として開始し、実施結果は[PCプレイ・観戦確認記録](pc-play-spectating-verification.md)へ記録する。既存の自動試験や過去の検証結果は参考にし、今回の実機合格へ自動転記しない。まず検証Pagesで実施し、本番へ同じ公開候補を反映した後、少数の専用テスト利用者で公開直前の確認を行う。本番確認は別途承認後に行い、準備中ページをこの計画だけで解除しない。

### 共通の主要導線

| ID | 確認内容 | 合格条件 |
| --- | --- | --- |
| D-01 | 初回訪問・解析拒否・観戦URL直訪問 | 登録・規約同意・無料特典受取を強制せず閲覧・観戦できる。解析拒否でも支障がなく、GAの送信がない |
| D-02 | 無料5枚の受取とゲスト名 | 受取は一度限り。再読込・ログアウトで再付与しない。固定ゲスト名と残高を確認できる |
| D-03 | プレイ開始・キャンセル・連打 | キャンセルで消費なし。正規開始1回に消費1枚。連打・通信再送で二重消費・二重開始しない |
| D-04 | READY・ポーズ・復帰・離席 | 意図せず動き出さず、説明と操作が一致。別のゲームへの移動確認が働き、離席後に筐体状態が残り続けない |
| D-05 | Google登録と元画面への復帰 | ゲーム終了後のランキング登録からも元の状態へ戻れる。初回登録の5枚追加と対象残高の引継ぎが一度だけ行われる |
| D-06 | 再ログイン・ログアウト・別端末 | ログアウトでトップに戻り、既存アカウントへ再ログインするとその残高が維持される。別ゲスト残高の自動合算や登録特典の再配布がない |
| D-07 | 日次補充・残高不足 | 3枚未満の差分だけを同日1回補充し、補充済みの不足時は翌日を案内。サーバー日付境界は自動試験と実日付で確認し、端末時計変更だけを証明にしない |
| D-08 | 終了・ランキング・再挑戦 | 終了演出後に画面遷移し、操作中の指がそのまま登録・再挑戦を押さない。ゲスト名は編集不可。登録・順位表示・再挑戦の消費が正しい |
| D-09 | 遊び方・プロフィール・通知 | 項目が読め、開閉・Esc・外側タップが意図通り。通知が操作を妨げず、自動消去と手動閉じるが動く |
| D-10 | 購入停止・非公開モード | 購入導線がなく、直接購入要求も拒否。公開しない対戦・協力が直接要求でも開始できない |
| D-11 | 退会・公開記録削除・解析撤回 | 専用テスト利用者で確認。再認証・確認操作・受付表示が働き、旧セッションを拒否。解析撤回後に新しいGA送信がない |

D-03/D-04/D-08の開始前失敗・開始後切断・リトライにおける消費/返却の期待値は、OP-03の運営ルールと実装を照合して先に確定する。「不具合ならすべて自動返却」とは案内しない。D-05/D-11で運営者本人のアカウントを新規登録・退会して試験しない。

### ゲーム別の確認

| ゲーム | PCで必須 | スマートフォンの試験項目 |
| --- | --- | --- |
| BUZZ BARRIER | 移動・低速移動・開始/ポーズ、かすり・シールド・被弾、ボス、ゲームオーバー/クリア、結果表示 | 相対スライド、画面端までの移動、指でUIを誤操作しない、終了直後の誤タップ防止 |
| DOT WAVE | 操作後の音声開始、リズム入力、攻防・ポーズ・再開・結果、キー押下がページスクロールと競合しない | タップと音声開始、画面回転後の位置、音の途切れ・入力しづらさ。Bluetoothの遅延とゲーム不具合を切り分ける |
| 深海サルベージ | 移動・開始/ポーズ・図鑑、調査・電力/船体表示、終了・結果からの復帰 | タッチ移動、図鑑・ポーズボタン、表示の見切れ、再開後の操作復帰 |

公開対象ゲームはWindowsとMacの両方で確認する。自然なゲーム終了を確認できていない場合は未確認として残し、デバッグ結果表示だけでクリアやゲームオーバーの動作を合格にしない。

### 観戦・回線・端末固有

| ID | 確認内容 | 合格条件 |
| --- | --- | --- |
| V-01 | PCプレイ→別端末のURL直訪問 | 登録なしですぐライブを見られる。自機・弾・ボス・終了演出が一致し、PC/スマホで位置がはみ出さない |
| V-02 | 人だかり・一覧・共有 | プレイ中筐体と観客表示が実状態を反映。共有先が観戦画面で、終了済み筐体も説明なく真っ黒にならない |
| V-03 | 観戦中のスクロール・画面回転 | iPhone/Androidでゲーム領域からページスクロールでき、縦横変更・アドレスバー伸縮でもボタンや説明が隠れない |
| V-04 | 別タブ・画面ロック・戻る | 裏から戻った際に古い映像を現在のライブと誤認させない。復帰待ち/終了を案内でき、余分な接続・筐体が残り続けない |
| V-05 | 短い切断と回線切替 | 専用テスト利用者でWi-Fi→モバイル回線、短いオフラインから復帰を確認。開始前後の状態・消費を照合し、観戦者はホスト操作権を得ない |
| V-06 | 音・タッチ・読みやすさ | 音が必要なゲームは操作後に音が出る。勝手な音声再生・文字選択・ズームによる操作不能、主要文字の見切れがない |
| V-07 | 同一Wi-Fiでの正規利用 | 1人のプレイと別の1〜2端末の観戦を短い通常操作で確認。意図しない接続拒否や他人の残高/プロフィール表示がない |

観戦は3ゲームすべてについてPC・iPhone・Androidで確認する。V-07は2〜3端末の機能確認であり、同時6人の耐久試験ではない。合成接続・ループ・限界測定・30分連続試験は実施しない。各確認が済んだら離席・切断し、使用量の余裕がなければ中止する。短い正常操作の成功を負荷試験の合格へ振り替えない。

## 5 合格判定と記録

ケースごとに次の形式で記録する。資格情報・Cookie・メールアドレス・個人識別用URLは残さず、必要な画面証跡も秘匿部分を除く。

| 日時 | リビジョン・環境 | 端末/OS/ブラウザ版 | ゲーム・役割 | ケースID | 結果 | 問題・再確認 |
| --- | --- | --- | --- | --- | --- | --- |
| 未実施 | 未確定 | 未確定 | 未確定 | D/V番号 | 未確認 | 担当者・証跡を追記 |

- 公開候補リビジョンを固定し、条件を変える修正が入ったら関係するケースを再確認する。異なるリビジョンの成功を継ぎ合わせて合格にしない。
- 個人情報漏えい、権限逸脱、二重消費、無料特典の繰り返し付与、主要導線の停止は公開を止める。単に既知の不具合と書いて許容しない。
- 特定ゲーム/端末だけの問題は、その組合せを提供対象から外せることを確認したうえで公開範囲を縮小できる。共通認証・残高・観戦権限の問題は対象を狭めて解決した扱いにしない。
- 見た目の軽微な課題は、影響・回避策・受容者・日付を記録して判断する。ブラウザのバックグラウンド制限等の制約も説明する。
- 継続的な接続切れ、正規利用への429、利用量/費用警告、問い合わせ対応不能が起きたら新規招待を止める。既存の運用手順で切り分け、復旧確認後に再開を判断する。

## 6 公開判断までの順序

1. 対象・人数・端末・提供モードの範囲案は運営者承認済み。招待経路・案内時間帯・問い合わせ運用を確定し、BT-01を完了させる。
2. 招待アクセスの境界、非公開モード制御、クレジット消費/切断ルール、問い合わせ手段を整える。
3. 検証環境で上記の実機確認を行い、BT-02/BT-03の証跡と未解決事項を整理する。
4. 規約・プライバシー・素材権利・本番専用設定などのP0を満たし、別途承認を得て本番へ反映する。本番で購入停止・特典・認証・観戦・監視を少数で再確認する。
5. 負荷試験保留に伴うリスク・対応できる人数・停止方法を明記し、運営者が限定公開の可否を判断する。負荷試験を省略して安全を実証済みとはしない。
6. 最初の5名へ案内し、問題を確認後に合計10名まで招待する。一般公開・人数拡大は別判断とする。
