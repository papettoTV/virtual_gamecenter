# 検証ブラウザ回帰の失敗診断

## 保持する証跡

固定8件のJSONから、固定ケースID（home / terms / privacy / game-navigation）、
desktop / mobile、結果、実行時間、失敗分類、固定テスト内の行番号だけを抽出する。
起動失敗、読めないレポート、不完全なレポートを区別する。8件成功・skipなしの
既存の合格条件は維持する。任意タイトル、認証設定、生のエラー本文、期待値・実値、
URL、ゲスト情報、添付ファイル、stdout/stderrは結果成果物へ転記しない。

`browserFailure` は実行直後、処理層、失敗成果物の各段階で許可項目へ絞る。
これは保護された制御へ配置後に有効になる変更で、developへの取り込みだけでは
既存の公開処理の診断は変わらない。

## デプロイしない先行診断

`tools/package-staging-browser-diagnostics.py` はコミット済みファイルのハッシュを
埋め込んだ人用起動スクリプトを生成する。作成・実行ともGitHub設定の変更は不要。
起動スクリプトは入力前にコード一致とNode.js 22を検査し、検証用Basic認証を
非表示で受け取る。値はチャット、ファイル、コマンド引数へ書かず、子プロセスの
stdinから渡す。GitHub・OpenAI・Cloudflareの鍵は入力せず、子環境にも渡さない。

対象は固定検証URL、SHA `0655696a661d2344edc3d0570b9037bc605b643d`。
HTTPと両SHA照合が合格した場合だけ、既存のブラウザ8ケースを1回実行する。
HTTP/WSは検証originだけ、Basic認証も同originだけ、Service Workerは無効。
検証ゲストは作成されるが、クレジットを受け取ったり実プレイへ了承したりしない。
Worker/Pages公開、Git更新、Secret保存、保護設定変更は行わない。

スクリーンショット等の一時出力は削除し、サニタイズ済み `result.json` だけを
`/private/tmp/pulbase-staging-browser-diagnostic-*/` に残す。成功でも失敗でも、
この読取診断を過去のActions実行の成功へ置き換えない。原因調査の証跡として扱う。

## 現在の検証範囲

- 秘密値入り・不正・過大・未知ケース・再試行付きの偽レポートを使う単体検査。
- ローカル外部通信禁止の固定8ケースで、意図的なSHA不一致を2件作り、
  homeのdesktop/mobileがfailed、その他6件がpassedと識別できることを確認。
  ローカルコピーのファイル名が異なるため失敗行はnull。実パスの行抽出は単体検査で確認。
- 診断改善後の実公開・回帰はまだ実施していない。

## 2026-11-01の先行診断

人がBasic認証を入力して実行した読取診断は、同じ配信SHA `0655696` で
HTTP 200・Worker/Pages両SHA一致・固定ブラウザ8件成功だった。再公開や
Cloudflare APIの利用はなし。元のActions失敗を再現した結果ではなく、
元実行にはケース詳細がないため、その時点の原因はまだ確定していない。

既存のtoolchain CIは親プロセスの環境でChromiumを起動していたため、
実公開時と同じ、PATHと検証用変数だけの隔離環境でも起動・ローカル描画を
確認する検査を追加する。鍵や実サイトは使わず、sandboxは有効のまま。
これは2プロジェクトの起動検査であり、検証環境の回帰8件の代用ではない。

原因がアプリコードなら自動担当の修正Issueで対応する。CI保守と#91/#99の
アプリ実装担当は混同しない。strict・bypass空・staging承認1回、main・本番未反映を維持する。

GitHub runner Ubuntu 24.04でも隔離env・sandbox有効の起動/ローカル描画2件が成功。
これも元の実サイト失敗の再現ではない。元実行の失敗原因を復元できないことと、
現在の同じ配信SHAで8件合格していることを分けて扱う。

人用配置の親はb0d2ff949dfb5ea3470a8ec943bfad9e55e2f89c、固定対象は既存7ファイル。
実差分はfixed-process、fixed-staging-operations、postmerge-runnerの診断3件だけで、
残り31件を維持する。公開workflow、ブラウザの8ケース、公開先や鍵は変更しない。
配置の適用は初期値では無効。一時的な保守例外が必要な場合も、人の明示許可と
管理操作なしには作成・実行せず、bypass空の運用条件を変更しない。
