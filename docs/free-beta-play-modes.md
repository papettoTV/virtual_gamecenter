# 無料ベータの提供モード制限

更新日：2026-10-21。[Issue #26](https://github.com/papettoTV/virtual_gamecenter/issues/26)。対象は3ゲーム共通。

## 提供範囲

- 提供するのはソロプレイ（CPU相手を含む）とライブ観戦。リトライ、共有、ランキングは維持する。
- 人間同士の対戦、乱入、再戦、協力は提供しない。画面の非表示だけではなく、Worker/DOが拒否する。
- `src/domain/play-mode-policy.ts` の公開モードは `solo` のみ。環境情報が欠けても許可を広げない。

## 強制する境界

| 入口 | 無料ベータの動作 |
| --- | --- |
| クレジット予約API | `challenge` / `rematch` / `versus` / `coop` の要求、本文/クエリの非公開モード指定を403 `game_mode_unavailable`で拒否。予約・プレイセッション・台帳を追加しない |
| 不明・不正なモード指定 | 不明なpurpose/mode、null、配列などを黙ってsoloへ変換せず400 `invalid_play_mode`。purpose省略は既存互換でsolo |
| 既存予約の確定API | 保存されたplay_sessionのmodeを確認し、非公開モードの確定を403で拒否。過去にcapturedでも新たな確定は許可しない |
| 予約の解放 | 引き続き本人分だけ解放可能。capturedの未使用分は既存の返却条件を維持。使用済み分を無条件に返却しない |
| WebSocket接続URL | modeクエリが非公開/不明なら接続を403で拒否し、DO接続枠を割り当てない |
| WebSocketの操作 | ソロ・観戦・退出・時計同期・受信確認・既存申込取消などの許可リストで制御。申込・承諾・準備・攻撃・結果・再戦・協力・未知の命令は拒否。startSolo/joinCabinetへのmode偽装も拒否 |
| 拒否応答 | WebSocketは`error`と`code: game_mode_unavailable`を返す。席・観客・試合・残高を変更しない。既存の頻度制限・失効確認は引き続き行う |
| 待ち行列 | 非公開時に次の対戦者を自動昇格しない。過去の申込取消・予約解放・退出による片付けは維持 |
| UI | Canvasゲームの対戦申込、DOT WAVEの申込/承諾/再戦、単体画面の同一端末2人選択を出さない。通信対戦を提供中とする説明も修正 |

ブラウザのURL・Cookie・入力JSONから環境や許可モードを変更することはできない。未知のWebSocket命令を無条件に許可しないため、将来モードを追加するときにも公開範囲の判断が必要になる。過去の対戦結果の参照まで禁止するものではない。

## ローカル開発とテスト

初期設定ではローカルもソロのみ。将来向けの既存対戦回帰テストは削除せず、ローカルWorkerでだけ `APP_ENV=local` と `LOCAL_MULTIPLAYER_ENABLED=true` の両方がそろった場合に実行する。公開UIの提供モードは別途soloのみで、開発用の対戦開始ボタンは追加しない。

`staging` / `production` / 環境未設定では、このフラグがtrueでも対戦を許可しない。今回Cloudflareの設定・Secret・本番ファイルへこのフラグを追加しない。

- 既存のメイン/対戦テストpoolはローカル明示設定で既存の申込・勝敗・再戦・失効検査を維持する。
- 新しい `npm run test:beta-modes` は無効設定の独立poolで実Worker/DOの拒否・状態不変・ソロ・観戦を検証し、`npm test`にも必須で含める。メインpoolからの分離はこの設定差のためで、試験の除外ではない。
- 旧対戦の二人分SLO履歴の検査はローカルで作った履歴フィクスチャとSLO関数で維持する。検証APIから新しい対戦を開始できることを前提にしない。
- UIは3ゲームの申込ボタン不在、DOT WAVEの2人選択不在とソロ/観戦表記、観戦中も共有が残ることを検査する。

## 検証反映・判定

専用PRの必須CI通過後にdevelopへ統合し、検証Pages/WorkerのSHA一致、専用ゲストによる直接HTTP/WebSocket拒否、ソロ開始・観戦・退出、実画面の導線を確認する。最終SHA・Actions・実施結果はIssue/PRの証跡へ記録する。反映前の単体テストをクラウド確認済みとは扱わない。

本番/main、DB移行、購入、監視設定・障害訓練、負荷試験と保留中の接続回復コードは対象外。今回の制限だけでBT-02/BT-03全体や無料ベータ公開判定を完了にしない。
