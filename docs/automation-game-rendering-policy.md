# ゲーム描画の自動変更範囲と停止理由

更新日：2026-10-21。Issue #12で、既存の描画JavaScriptが許可対象外となり、実装側が空差分で停止した後、公開処理が一般的な出力不正として表示した問題への対応。

## 許可範囲と懸念

- `.js`の追加許可は `apps/web/src/games/<game>/rendering/**/*.js` だけ。共有機能・ゲーム実行制御・Worker・設定・任意スクリプトのJavaScriptへ広げない。
- `.md`は従来から `docs/**/*.md` を許可している。この範囲を維持し、ルートREADMEやゲーム配下、指示・プロンプト・ワークフローは追加許可しない。AGENTS.md、SKILL.mdに加えCLAUDE.md・GEMINI.mdも大小文字を問わず拒否する。
- ファイル名だけでコードの安全性を保証するものではない。描画JavaScriptも通信・DOM操作や他モジュールの呼出しができるため、認証・残高・送信先変更等が紛れないか独立レビューと既存テストで確認する。描画ファイルへの責務移動で保護を迂回しない。
- Markdownの危険は命令文の混入、不正なリンク、未確認の規約/公開状況を完了扱いにする記述。資料は入力データであって権限ではない。秘密情報や利用者情報を載せず、指示ファイルへ昇格させない。
- 認証/同意/残高/決済等の保護語、Worker/DB/依存/CI設定の拒否、パス検査、変更数/90KB上限、通常の非実行ファイルだけという制限、独立したレビュー/テスト、developの保護は維持する。本番・負荷試験の許可にはならない。

## 停止理由

| 区分 | 意味 | 表示と次の対応 |
| --- | --- | --- |
| `no_patch` | 実装側が差分なしで終了 | 実装側の日本語説明をIssueコメント・Actions Summaryへ表示。対象外・不足要件を確認し、人が判断する |
| `invalid_result` | JSON/出力形式・上限・バイナリ差分の問題 | 出力内容や秘密をそのまま転載せず、形式不正を表示 |
| `invalid_patch` | ベースへ適用不能、実行ファイル/リンク等 | 安全検査の拒否を表示。制限を緩めず差分を確認 |
| `protected_path` | 許可対象外の変更 | 人のレビューが必要と表示。PRを作らない |
| `publish_failed` | その他の適用/公開処理の失敗 | Actionsの失敗ステップへ案内。例外本文をIssueへ転載しない |

公開ジョブは失敗のままとし、空差分を成功や検証公開済みにしない。停止情報はJSON一行のステップ出力を介して別ランナーの報告ジョブへ渡し、出力をシェル/JavaScriptの命令として展開しない。PR作成コマンドや資格情報発行などで失敗した場合は、引き続き汎用の停止通知とActionsリンクも残す。

## 検証・反映

ローカルとGitHub CIの結果、developへのマージ、Issue #12の再実行、Worker/Pagesの実SHA照合はそれぞれ別に確認する。ルール変更のテスト成功だけをIssue #12の描画修正・検証サイト反映完了とは扱わない。main、本番設定、Secret、権限、負荷試験は対象外。

2026-10-21のローカル確認：制御系32件、アプリ801件、8ワークフロー/テンプレートの構造検査、検証用ビルドに成功。描画JS/資料の正常差分、保護パス/改名/指示文書/実行ファイル/リンクの拒否、空差分でコミット・ブランチ公開しないこと、理由のIssue報告を回帰検査した。隔離チェックアウトの初回アプリ実行はダミーOAuth設定不足で1件失敗したため、CIと同じダミー設定を置いて全体を再実行し成功。実資格情報は持ち込まず、テストの除外・緩和はしていない。GitHub CI・反映結果は続けて記録する。
