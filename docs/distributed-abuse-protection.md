# 分散アクセス・全筐体横断の乱用対策

更新：2026-10-16。無料ベータ向けの初期上限。同一回線24人の検証を踏まえIP予算と個人予算を分離。検証のみへ反映し、本番の公開・有料プラン変更は行わない。

## 構成と境界

- 既存の拠点単位Native Rate Limitingと本文/WSサイズ検査を第一段に維持する。
- API要求はIPの環境別ハッシュから16個の固定SQLite Durable Objectへ振り分ける。拠点が変わっても同じキーは同じオブジェクトへ到達し、SQL transactionSyncで検査と加算を原子的に行う。
- 検証済みの利用者IDも別の固定シャードへ照合する。Cookie文字列を本人IDとして信頼せず、IPやログイン端末が変わっても同じ利用者の予算を共有する。シャード共有予算は要求につき1回だけ消費する。
- 希少な筐体/接続枠だけはゲームセンター単位の `admission` オブジェクトで調停する。フレーム・各WSメッセージ・静的アセットはこの共有オブジェクトを通さない。
- Worker/環境のDO namespaceは分離。`v2` の `AbuseGuard` SQLite移行を追加。設定検査で別Workerへのbinding転用・移行漏れ・成果物の環境違いを拒否する。

## 頻度予算

カレンダー分とUTC日の固定窓。各IP・検証済み利用者と、そのIPシャードの共有予算を両方検査する。拒否された本人検査の前に共有予算を消費する場合がある。

| 種別 | 1シャード 分/日 | IP 分/日 | 利用者 分/日 | 16シャード合計の日次上限 |
| --- | ---: | ---: | ---: | ---: |
| 参照API | 600 / 30,000 | 600 / 30,000 | 120 / 2,000 | 480,000 |
| 更新API | 180 / 6,000 | 120 / 3,000 | 60 / 500 | 96,000 |
| bootstrap | 60 / 1,000 | 60 / 1,000 | 10 / 100 | 16,000 |
| 初回特典 | 30 / 300 | 30 / 100 | 10 / 20 | 4,800 |
| 認証API | 60 / 1,000 | 60 / 300 | 10 / 100 | 16,000 |
| WS接続要求 | 120 / 2,000 | 90 / 1,000 | 30 / 500 | 32,000 |

これは受付予算であり、他シャードに余裕があっても混雑したシャードは拒否する。共有回線・NATや長時間のポーリングでは複数利用者がIP予算を共有する。無料ベータの実利用に合わせて調整し、枠を増やす前に費用・負荷を確認する。分の境界では短時間に2窓分の要求が可能なので、秒単位のネイティブ/WS検査は省略しない。

超過は429・no-storeと、超過した窓の残り秒数を `Retry-After` で返す。共有制限の停止・binding欠落・信頼するIP欠落では503で止め、業務処理へ進まない。ローカルでCloudflare IPヘッダーがないCLI要求だけは分散検査を省略する。health・署名付きWebhookは頻度制限の例外だが、認証・署名・本文上限は維持する。

## 全筐体の枠

| 対象 | 上限 |
| --- | ---: |
| 同時接続枠（全ゲーム/筐体） | 256 |
| 同一IPの同時接続枠（全筐体） | 64 |
| 同一検証済み利用者の同時接続枠（全筐体/端末） | 8 |
| 直近24時間の異なる筐体割当（稼働中は保持） | 200 |

新しい筐体DOを呼ぶ**前**に枠を確保する。無限にURL・IP・ゲストを変えても、全体の割当上限を超えて新しい筐体DOを生成し続けない。枠拒否では残高操作やプレイ開始へ進まない。筐体内64接続/IP32/セッション4の検査も残す。

一覧更新は3秒から10秒へ変更し、非表示タブでは停止する。3ゲームを24人が閲覧する場合の定常要求は毎分432、1時間25,920。単一IP/シャードの日次30,000には収まるが、長時間利用・別の利用者とのシャード衝突・他API消費分は余裕を減らす。この枠は全利用者の24時間連続利用を保証せず、Cloudflareの無料枠を超えないことも保証しない。[負荷検証の範囲と証跡](free-beta-load-verification.md)を参照。

Workerが発行する割当IDをprivateなDO転送ヘッダーに置く。外部が付けた同名ヘッダーは削除する。失敗したupgrade・切断・セッション失効・違反切断で返却し、重複返却は安全に無視する。古いattachmentはDO復帰時に、外部RPCをstorage初期化の排他区間に入れずに割当へ移行する。

異常終了などで返却が失われた枠は5分alarmで筐体の実ソケットと照合する。60秒以内の処理中割当や、照合できない筐体の枠は勝手に解放しない。再照合中に作られた新しい枠も古いスナップショットで消さない。停止中は枠不足として失敗することがあり、実接続を未確認のままTTLだけで容量を空けない。

## 保存と運用

制限キーはIP/利用者IDの環境別SHA-256。生IP・Cookie・プロフィール名をSQLiteやエラーに保存しない。頻度記録は期限後の要求/5分回収で削除。接続枠は稼働中のみ、筐体割当は最後の割当から24時間以上で非稼働なら回収する。ハッシュは匿名化の保証ではない。[保存期間](data-retention-and-deletion.md)・プライバシーポリシーへ追記。

429が増えたら種類・共有回線・枠返却・再照合障害を先に確認する。残高を直接変えたり、ユーザー名をリセットしたり、ガードを外したりしない。アプリが停止している場合は503と監視メールを確認する。監視の条件は[利用量通知](cloudflare-usage-monitor.md)を参照。

- 大規模な地理分散負荷やPC/iPhone/Androidの実機評価は未実施。正規利用への影響はベータで計測し調整する。
- **絶対的な支払い上限・包括的DDoS対策ではない。** 拒否要求にもWorker/DO利用量は発生する。共有制限自身のSQL・alarm・照合RPCも無料枠を消費する。公的ページの描画・帯域・多数IPからの入口負荷はCloudflare基盤/WAF/Turnstile等の別レイヤーで継続検討。ネイティブ制限と費用/利用量通知は維持する。
