# 無料ベータ公開前のセキュリティレビュー

更新：2026-10-13。EN-03の初回点検。検証環境が対象で、本番公開の承認・包括的な監査完了ではない。

## 今回の確認と修正

| 対象 | 確認・対応 | 証跡 |
| --- | --- | --- |
| ログイン後の残高 | Chromeの検証サイトで5枚表示、ログアウト後0枚のゲストへ切り替わり、再ログインで元の5枚に戻る | 実ブラウザ操作と検証D1の読み取り照合。登録特典は1回・5枚で二重付与なし |
| ログアウト | トップへ遷移、登録者向け操作とログアウトボタンが消える | 実ブラウザ操作。自動テストでは旧セッションのプロフィール変更が401になることも確認 |
| ログイン通知 | 既存ユーザーにも「登録完了・5枚追加」と表示する不具合を修正 | 認証結果を新規登録・特典なしの再登録・既存ログインに分離。実際の台帳挿入結果に基づいて通知 |
| API/観戦接続のOrigin | 更新API・WebSocketに共通の入口検査を追加 | staging/productionでは同一Origin必須。別サイト・本番サイトから検証サイト・null・Origin欠落を403。ローカルのOrigin欠落は既存テスト/CLIのため許容し、明示した別Originは拒否 |
| 決済Webhook | ブラウザOrigin検査の例外とし、既存の署名検証を維持 | Origin欠落が同検査で拒否されず、署名なしは成功しないテスト |
| 個人の残高レスポンス | platformJsonにprivate, no-storeを指定 | bootstrapレスポンスのヘッダー検査 |
| 環境分離 | Pagesの環境ヘッダー上書きとWorkerの不一致拒否を維持 | 既存gateway統合テスト |

Origin検査はブラウザからの意図しない操作を防ぐ境界であり、Originを偽装できるHTTPクライアントへの認証や乱用対策の代替ではない。WebSocketの101応答は従来どおり透過する。[Cloudflare WebSockets公式資料](https://developers.cloudflare.com/workers/runtime-apis/websockets/)も参照。

## 未完了の点検・対応

今回の修正は検証Workerへ反映済み。全455テスト・型検査・検証ビルド成功。反映後のGoogle再ログイン通知/残高/ログアウトと、専用ゲストのゲーム開始・ライブ観戦同期を実環境で再確認した。実APIでも不正Origin4種類を拒否し、個人レスポンスのno-storeを確認。本番には反映していない。

1. 筐体の役割ごとの全メッセージ、所有権、ログアウト/退会後の既存WebSocket権限を検査する。
2. API本文とWebSocketメッセージのサイズ上限を統一し、接続数・筐体数・無料特典の乱用を制限する（EN-04）。
3. OAuth失敗ログ、セッション・個人情報、URLクエリを含む外部ログの保持/マスキングを確認する。
4. 結果登録のプレイとの紐付け、重複登録、クライアント申告値の不正対策を検証する（EN-05）。
5. Basic認証の比較方法、個人API全体のキャッシュ方針、セキュリティヘッダーを点検する。
6. 本番リソース設定、復元、監視・通知、PC/iPhone/Androidの実機検証を別途実施する。

重大な未解決事項を残したまま、EN-03や無料ベータ公開判定を完了にしない。
