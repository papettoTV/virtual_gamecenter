### 同日追加：接続受理と失効の競合・後処理失敗

コード点検で、本人確認後の`player_cabinets`書き込み待機中にセッションが失効し、失効RPCが未受理のソケットを見つけられない場合、古い本人情報のまま接続を受理して初期状態を送る隙間を確認した。既存の操作時DB検査は残っており、この隙間だけで不正プレイやクレジット消費が成立したと断定するものではない。

- ソケット受理・attachment保存後、初期状態を送る前にセッション期限とプレイヤー削除状態をDBで再検査する。検査失敗時も閉じる。検査待機中に失効RPCが処理された場合も、revokedを再確認して初期状態を送らない。
- 失効の印を最初のawaitより前に保存する。退出・永続化や枠返却が失敗してもfinallyで1008切断し、同一セッションの他ソケットの失効処理も開始する。返却確認の再試行に備え、閉じるattachmentにadmissionIdを残す。返却先が継続障害の場合の即時枠回復を保証するものではない。

- 全705テスト（通常581、DO補助20、復旧3、解析11、公開設定/素材19、利用量監視6、死活/復元/ログ48、負荷試験ツール単体17）、型検査・stagingビルド成功。既存の大きなJSチャンク警告は残る。テストに必要な`cloudflare:test`は既存のplugin構成に追加し、通常pool構成と重複実行しない。

### 同日追加：操作処理中の失効・失効RPC障害

操作中に外部DB/RPC待機を挟む箇所を点検し、予約照合後のソロ開始、プロフィール再取得、退出を挟む再入室、一覧更新後のキーフレーム配信で、待機前のattachmentを再使用する経路を補強した。

- 接続の現在のclientId・playerId・セッションハッシュ・役割とOPEN/revoked状態を待機後に再照合。準備完了・再戦予約では現在の対戦オブジェクト・matchId・状態も再照合する。失効済み/切断中の接続は検索・送信対象から除外する。
- 筐体からの予約照合・使用記録INSERTには、同じSQLでセッション期限・所有者・削除状態を条件に加える。使用記録の書き込み後に接続失効を検出した場合は、その操作固有のusageIdだけを取り消し、既存の冪等な未開始返却処理へ戻す。他のプレイの使用記録や開始済みプレイの消費は取り消さない。
- セッション再検査のDBエラーも、操作を進めず接続を切断する。高頻度配信の最大5秒キャッシュは維持する。
- ログアウトではDBセッション失効を先に確定し、その後の筐体一覧取得/RPC失敗でゲストCookieへの切替まで失敗しないようにした。筐体ごとに結果を回収し、一時的な接続喪失だけ既存の最大3回再試行を適用する。恒久エラー・過負荷を再試行し続けない。警告は固定カテゴリ・件数・再試行番号・分類だけで、Cookie・セッションハッシュ・生例外は出さない。

| 確認 | 結果・範囲 |
| --- | --- |
| 3ゲームの開始・映像更新・再入室中の失効、DOTプロフィール取得中の失効 | ローカル実DO/D1の10ケースで1008切断、席/映像の復活なし。開始中断の3ケースは使用記録0件・1枚だけ返却も確認 |
| 予約使用のSQL条件 | 3ゲーム×失効/期限切れ/削除の9ケースで、使用記録が作られない |
| ログアウト時の失効障害 | 恒久・一時回復・一時継続・過負荷・一覧取得失敗の5ケースで、旧セッション無効、新しいゲストCookie、他筐体への通知継続、秘密値非出力を確認 |
| 失効RPC失敗後の実ソケット | 次の制御メッセージで旧接続が1008、匿名観戦接続のclockPingは継続。失効RPC失敗をログアウト成功と区別して記録する |

これは全操作の全順序を網羅した証明ではない。別システムであるD1とDOの完全な原子性、RPC障害時の即時一斉切断、何も送信しないアイドル接続の即時切断は保証しない。継続障害時は次の制御メッセージ/高頻度配信の再検査が安全側の境界となり、後者は最大5秒キャッシュの影響がある。RPCの試行数は制限するが、サービス側の応答待ち時間自体を独自の期限で打ち切る仕組みは今回加えていない。失効RPCの失敗警告を集計・通知する運用、永続化/枠返却が継続して失敗した際の復旧確認は残す。

| ログイン後の残高 | Chromeの検証サイトで5枚表示、ログアウト後0枚のゲストへ切り替わり、再ログインで元の5枚に戻る | 実ブラウザ操作と検証D1の読み取り照合。登録特典は1回・5枚で二重付与なし |

| ログイン通知 | 既存ユーザーにも「登録完了・5枚追加」と表示する不具合を修正 | 認証結果を新規登録・特典なしの再登録・既存ログインに分離。実際の台帳挿入結果に基づいて通知 |

Origin検査はブラウザからの意図しない操作を防ぐ境界であり、Originを偽装できるHTTPクライアントへの認証や乱用対策の代替ではない。WebSocketの101応答は従来どおり透過する。[Cloudflare WebSockets公式資料](https://developers.cloudflare.com/workers/runtime-apis/websockets/)も参照。

## 未完了の点検・対応

### 2026-10-14：既存WebSocketのセッション失効

- 接続時に検証済みセッションのハッシュをattachmentに保存。Cookieの生トークンは保存・配信しない。
- ログアウト時に該当プレイヤーの既知の筐体へ失効RPCを送り、同じセッションの接続のみ退出/1008で切断。他端末の同一ユーザーと、他ユーザーの観戦接続は残す。
- 操作メッセージではDBのセッション有効性と削除状態を再確認。高頻度のライブフレームだけは最大5秒キャッシュし、毎フレームのD1照会を避ける。旧attachmentはハッシュを持たないため操作時に閉じ、再接続を必要とする。
- ISO形式の期限とSQLiteのCURRENT_TIMESTAMPを文字列比較すると同日内の期限切れを取り逃がすため、HTTPとWSの判定をdatetime(expires_at)で日時比較するよう修正。同日内の1分前をISO形式で設定する回帰テストを追加。
- 匿名の観戦は維持し、匿名のプレイヤー席取得は拒否。JSONのnull等の不正形式も例外ではなくエラー応答にする。
- テストで複数筐体の同一セッション切断、他端末/観戦者の継続、DB上の失効、不正形式、匿名観戦を確認する。退会時の接続切断は既存テストも継続する。
- 接続受理とログアウトの競合・切断後処理失敗は2026-10-20の追加点検で限定補強した（上記）。操作処理中の全競合、RPC継続障害、自然期限切れのアイドル観戦接続は追加点検が必要。失効キャッシュの最大5秒は「全状況で即時切断」とは異なる。
- 全459テスト（Vitest434件＋解析11件＋公開設定14件）、型検査・検証ビルド成功。検証Worker version `1cdcca0c-6289-49f6-9ebb-5d5c1636bb6d`へ反映済み。
- 実develop Pagesで専用ゲスト1件の期限だけを変更し、期限切れHTTPが401・既存WSが1008で切断・匿名観戦者の接続維持を確認。通常の消費/ゲーム開始/観戦フレーム配送も再確認。既存利用者のセッション・本番DBは変更していない。
