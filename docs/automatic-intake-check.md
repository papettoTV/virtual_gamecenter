# 二重受付を防ぐ自動実装の通常運用

- `実装:自動` のラベル付与で自動実装を開始する。ラベルなしのIssueは手元実装とする。
- 同じIssueの既存PRがあれば、別PRを作らない。Issue・PRのタイトルと本文は日本語で記述する。
- 必須CIと独立Codexレビューの成功後、`develop`へ自動マージする。
- マージ後の実SHAのCI成功から検証公開を自動起動する。人がstaging承認を1回行い、検証公開・HTTP回帰・ブラウザ回帰を各1回実施する。
- `main`への反映・本番公開には、別途人の判断が必要となる。

この文書は運用手順であり、未実施の試験や公開の成功を示すものではない。
