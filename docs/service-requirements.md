# オンラインゲームセンター サービス要件

## 1. 文書の目的

本書は、オンライン上に一軒のゲームセンターを再構築するサービスについて、企画者へのヒアリングから得られた思想、顧客体験、サービス機能、運営方針を要件として定義する。

個別ゲームの詳細なルールや実装方式ではなく、ゲームを遊ぶ人、観る人、ゲームを提供する開発者、店舗を運営する事業者に共通するプラットフォーム要件を対象とする。

## 2. サービス概要

### 2.1 サービス定義

本サービスは、登録不要でライブプレイを観戦でき、クレジットを使ってゲームへ挑戦できるオンラインゲームセンターである。

単にブラウザゲームを並べるのではなく、現実のゲームセンターで行われていた次の行動をオンライン向けに再構築する。

- 店内を眺める
- 人だかりのできた筐体を覗く
- 上手いプレイや白熱した対戦を観る
- 攻略や相手の特徴を観察する
- クレジットを投入し、本気の一回に挑む
- 観戦から乱入、対戦、協力へ移る
- 自分のプレイを仲間へ共有し、観客を呼ぶ

### 2.2 中心価値

> 本気のプレイが、人を呼ぶ。

プレイヤーがハイスコア、勝利、攻略へ本気で挑むからこそ、そのプレイには観戦する価値が生まれる。観客が集まることで熱気が生まれ、その熱気が新しい観客と次の挑戦者を呼ぶ。

観客を集めること自体をプレイヤーの主目的にはしない。プレイヤーの第一の評価軸は、ハイスコア、勝利、攻略などのゲーム内成果とする。観客の存在は、その挑戦を見届けることによる承認と、挑戦を続ける動機を与える。

### 2.3 ブランド体験

- 懐かしいアーケード文化と現代的なオンライン体験の比率は、おおむね7対3とする
- 現実のゲームセンターへ足を踏み入れた感覚を与える
- 3D空間の忠実な再現ではなく、ゲームセンターで自然に取っていた行動を現代的なWeb UIで再現する
- UFOキャッチャーやメダルゲーム中心の現代的なゲームセンターではなく、ビデオゲーム筐体を中心にプレイヤーと観客が集まる文化を表現する
- 少し暗く、画面、基板、ネオン、電子信号が発光する非日常的な空間とする
- 金属製の筐体、コイン、基板、電子音を想起させる、硬質でゲームらしい表現とする
- ログインを強制せず、入口は開かれているが、見つけた人が仲間に教えたくなる少し特別な秘密基地として感じられるようにする

## 3. 背景と解決する課題

### 3.1 原体験

かつてのゲームセンターでは、限られた小遣いとプレイ回数を有効に使うため、自分で遊ぶだけでなく、他人の上手いプレイを観て楽しみ、攻略を学ぶ文化があった。また、家庭では遊べないゲームと出会うワクワク感があった。

### 3.2 現代のゲーム体験に不足しているもの

- 他人のプレイを偶然、生で観る機会が少ない
- 基本無料や購入済みゲームでは、一回のプレイを失う緊張感が弱い
- ランダムマッチングでは、対戦相手を観察してから挑む余地が少ない
- 上手いプレイそのものではなく、配信者の知名度や話術に観客が集まりやすい
- ゲームを遊ぶ場所と、プレイを観る場所が分断されている
- 初心者が上級者に一方的に倒され、興味を失う危険がある

### 3.3 提供する解決

- 観戦URLを開くだけで、登録なしにライブプレイを観られる
- 人だかりを可視化し、面白いプレイを発見できる
- 観戦して相手やゲームを理解してから、対戦、協力、ソロプレイへ移れる
- クレジットによって一回のプレイに区切りと緊張感を持たせる
- プレイと観戦を同じ筐体・同じ時間の体験として統合する
- プレイヤーの集中を守りながら、観客が増える気配を控えめに伝える

## 4. ターゲット

### 4.1 初期ターゲット

- 30〜50代を中心とする、ビデオゲーム全盛期のゲームセンターを知る人
- ハイスコア、対戦、協力、攻略など、技術の向上を楽しむ人
- 自分で遊ぶだけでなく、上手いプレイや白熱した勝負を観ることに価値を感じる人
- 一回のプレイへ集中して取り組みたい人

### 4.2 拡張ターゲット

- 観戦URLから初めてゲームへ触れる人
- プレイを観て攻略を学びたい人
- 圧倒的な技術へ憧れ、自分も挑戦したい人
- 自作ゲームを、プレイヤーと観客が集まる筐体として提供したい開発者
- 日本国外のアーケード文化、ライブゲーム、競技ゲームの愛好者

## 5. サービス原則

### 5.1 観戦を最初の入口にする

- 初めて訪れた人には、まずプレイ中の筐体を観てもらう
- トップページでは、ゲーム一覧だけでなく、現在最も観客が集まっている筐体を優先的に発見できるようにする
- 上手さを運営が判定して推薦するのではなく、人が集まっている事実を熱気の主要指標とする
- 観戦はログイン、規約同意、クレジットを要求しない

### 5.2 ライブを主役にする

- 歴代最高記録だけでなく、今日、その場で生まれる名勝負・名プレイを主役とする
- 初めて訪れた人でも、現在進行中のプレイをすぐ楽しめるようにする
- 観戦URLを開いたら、説明画面や観戦開始ボタンを挟まず、ライブ映像を直ちに表示する
- 初期段階ではリプレイよりも、その場に居合わせた人だけが体験できる一回性を優先する
- 将来リプレイを導入しても、ライブ観戦を中心体験として維持する

### 5.3 プレイヤーの集中を守る

- プレイヤー画面にはゲーム進行に必要な情報を優先して表示する
- 観客コメント、リアクション、通知をプレイの妨げにしない
- 観客増加は、画面周辺の光や電子的な脈動など、控えめな環境変化として伝える
- 歓声やざわめきは、集中を損なわないことを検証したうえで段階的に導入する
- プレイ終了後には、最大同時観戦者数、観客増加、共有、反応などを確認できるようにする

### 5.4 観客同士の熱気を作る

- 観戦画面を開いた瞬間、他にも人が一緒に観ていることを感じられるようにする
- 正確な観客数は確認可能にするが、数字そのものを主役にしない
- 観客の密度、筐体の脈動、反応、コメントなどを使い、盛り上がりを感覚的に表現する
- 観客同士はコメントやリアクションで盛り上がれるようにする
- プレイヤーへの通知と観客同士の会話は分離する

### 5.5 一回は濃く、関係は長くする

- クレジットは、ユーザーの時間を奪うためではなく、一回のプレイを大切にするための仕組みとする
- 無料ゲームをだらだら遊ばせるのではなく、限られた一回へ集中する体験を作る
- 一回のプレイ時間は、数分から数十分を基本とする
- いつでもふらっと立ち寄れ、気づけば何度も通い、長くやり込んでいる居場所を目指す
- 観戦と店内探索は気軽にし、プレイ開始時だけ適度な緊張を作る

### 5.6 誰でも入れ、勝敗は腕前で決める

- サイト閲覧と観戦にログインを強制しない
- アカウントは利便性を高めるものであり、サービス利用の必須条件にしない
- 課金によってゲーム内の勝敗を有利にしない
- 課金は原則としてプレイ用クレジットと、将来のプロフィール装飾など勝敗に影響しない要素に限定する
- 初心者狩りを抑止し、ゲームへ興味を持ったばかりの人が一方的に排除されない仕組みを設ける

## 6. 空間モデル

### 6.1 一軒のゲームセンター

初期サービスは、無数のゲームを並べる巨大プラットフォームではなく、店主の思想と選台方針が見える一軒の小さな名店として提供する。

- 店内には、運営が選んだゲームだけを設置する
- ゲーム数の多さではなく、選ばれた理由と店の文化を価値にする
- ユーザーが「このサービスを使う」ではなく、「この店へ行く」と感じられるようにする
- 将来は、本店の大型化、テーマ別店舗、期間店舗、複数店舗へ拡張できる構造にする

### 6.2 筐体の役割

筐体はゲームを表示する機械ではなく、プレイヤーと観客が集まる場の中心である。

- プレイヤーにとっては、本気の一回へ挑む舞台である
- 観客にとっては、同じ瞬間を共有する観戦場所である
- サービスにとっては、ライブプレイ、観客、対戦申込みを結びつけるリアルタイムルームである
- 筐体ごとに共有可能な固有URLを持つ

筐体を中心に人が集まる構造は、焚き火をメタファとする。ただし、炎を具体的に描くのではなく、暗い店内に電子的なパルスや信号が広がる抽象表現とする。

### 6.3 現実の行動とオンライン機能の対応

| 現実のゲームセンター | オンライン上の機能 |
|---|---|
| 入店する | 店舗トップを開く |
| 店内を見回す | ゲーム・プレイ中筐体を一覧する |
| 人だかりを見る | 観客が集まる筐体を発見する |
| 後ろから画面を覗く | 共有URLから即時観戦する |
| クレジットを投入する | クレジットを消費してプレイを開始する |
| 乱入する | 観戦中の筐体へ対戦を申し込む |
| 隣で協力する | 観戦中の筐体へ協力を申し込む |
| 筐体を離れる | プレイ終了後に店舗トップへ戻る |
| 仲間を呼ぶ | 観戦URLを共有する |

## 7. 主要ユーザージャーニー

### 7.1 観戦からプレイヤーになる

1. 観戦URLまたは店舗トップからプレイ中の筐体を開く
2. 余計なステップを挟まずライブプレイが始まる
3. 他の観客の存在と人だかりを感じる
4. ゲームの面白さ、攻略、プレイヤーの技術を知る
5. 自分も挑戦したいと思う
6. 空き筐体またはプレイ開始導線を選ぶ
7. 必要ならWelcome Creditを受け取る
8. クレジットを投入してプレイする

### 7.2 プレイヤーが観客を呼ぶ

1. プレイヤーが筐体でゲームを開始する
2. 観戦URLを仲間へ共有する
3. 仲間がURLから即時観戦する
4. 観客が増えるほど筐体のパルスが控えめに強くなる
5. プレイヤーは集中を維持しながら、見届けられていることを感じる
6. プレイ終了後、結果と観戦状況を確認する

### 7.3 観客が新しい観客を呼ぶ

1. 観客が面白いライブプレイを見つける
2. 特定のプレイを仲間にも見てほしいと感じる
3. 筐体の観戦URLを共有する
4. 新しい観客が同じライブプレイへ直接入る
5. 関係性の薄い観客まで増えることで、人だかりが大きくなる
6. 店舗トップでも盛り上がっている筐体として発見されやすくなる

### 7.4 観戦から対戦・協力へ移る

1. 観客がプレイヤーの実力、動き、ゲーム状況を観察する
2. 対戦または協力を申し込む
3. プレイヤーは集中を妨げないタイミングで申込みを確認する
4. プレイヤーが承認すると、必要クレジットを確認・仮確保する
5. ソロプレイ終了時または合意した開始タイミングでモードを切り替える
6. 同じ筐体で対戦または協力プレイを開始する

## 8. 機能要件

### 8.1 店舗トップ

- 一軒のゲームセンターへ入店したと理解できる構成にする
- 店内で現在プレイ中の筐体を表示する
- 最も観客が集まっている筐体を優先的に発見できるようにする
- ゲームごとにプレイ中筐体と観客の集まりを確認できるようにする
- 空き筐体からソロプレイを始めるか、プレイ中筐体を観戦するか選べるようにする
- ゲーム一覧だけでなく、「今、何が起きているか」を中心に構成する
- 利用規約、プライバシーポリシー、問い合わせ先、運営情報へ到達できるようにする

### 8.2 観戦

- 共有URLからログインなしで観戦できる
- 観戦開始前の確認画面を挟まない
- 途中参加時も、現在のゲーム状態を速やかに再現する
- プレイヤーと同等に近いリアルタイム性を確保する
- 観戦者はゲーム操作へ干渉できない
- 観戦者数、観客の気配、コメント、リアクションを表示できる
- 観戦者は同じライブプレイのURLを再共有できる
- 観戦中のゲームを自分で始める導線を表示する
- 対戦・協力申込みを行えるようにする
- プレイヤー終了時は勝手にリスタートせず、プレイヤーの次の選択を待つ状態を表示する

### 8.3 盛り上がり判定

盛り上がりは、主として現在の同時観戦者数と、その広がりで判定する。

- 少人数の強いリアクションより、大人数が静かに観ている状態を高く評価する
- プレイヤーが直接呼んだ近しい観客だけでなく、その外側へ観客が広がっていることを重視する
- リアクション数やコメント量は補助指標とし、簡単に順位を操作できないようにする
- 店舗トップでは、盛り上がりを数字だけでなく、発光、脈動、密度などで感覚的に表現する
- 正確な観戦者数は、希望するユーザーが確認できるようにする
- 将来は観客増加速度、共有経由流入、ゲーム内の重要局面を補助指標として検討する

### 8.4 ソロプレイ

- 空き筐体を選択して開始できる
- ゲーム開始前に必要クレジットと現在残高を示す
- ゲーム開始意思の確定後に残高を確認し、開始条件が揃ってから仮確保する
- ゲーム起動成功時にクレジット消費を確定する
- ゲーム終了後は結果、ランキング、リトライ、別ゲームへの移動を選択できる

### 8.5 対戦・協力プレイ

- 観戦者からプレイヤーへ申込みできる
- プレイヤーは申込みを承認、保留、拒否できる
- プレイヤーの集中を妨げない通知方法とタイミングを採用する
- ホストはソロプレイ開始時に消費したクレジットを対戦へ引き継ぎ、対戦開始時に追加クレジットを消費しない
- 挑戦者は対戦申込み時に1クレジットを仮確保する
- ホストが申込みを拒否した場合、申込みが時間切れになった場合、または対戦開始前に不成立となった場合は、挑戦者の仮確保を解除する
- ホストが承認し、対戦ゲームの起動に成功した時点で、挑戦者の仮確保を消費として確定する
- 対戦へ切り替えると現在のソロプレイが終了することを、ホストが承認する前に明示する
- 対戦終了後の再戦では、ゲームごとに定めた側が新たにクレジットを投入する。初期仕様では負けた側が1クレジットを投入する
- 対戦では、観戦によって相手の実力や特徴を理解したうえで挑戦できる
- 初心者保護のため、経験差が大きい対戦の警告、申込み制限、初心者保護状態などを将来導入できるようにする
- ゲームごとに勝敗、協力成果、再挑戦条件を定義できるようにする

### 8.6 クレジット

- 観戦、ゲーム選択、店内探索では消費しない
- プレイ開始時にのみ消費する
- クレジット残高不足は仮確保前に判定する
- 無料クレジット、有料クレジット、仮確保残高を分離する
- 無料クレジットは端末単位で一度だけ付与する
- 有料クレジットはアカウント登録によって複数端末で共有できる
- 決済によってゲーム内の能力や勝敗を有利にしない
- 起動前の不成立、対象となるシステム障害では仮確保解除または返却を行う
- すべての残高変更を台帳で管理し、冪等性を保証する

### 8.7 匿名利用とユーザー登録

- サイト訪問、店舗閲覧、観戦、無料クレジットでのプレイにユーザー登録を要求しない
- 匿名プレイヤーには変更不能なシステム名を付与する
- ユーザー登録後は、表示名とプロフィールアイコンを設定できる
- 匿名状態のクレジット、プレイ情報、ランキング結果を登録ユーザーへ引き継ぐ
- ユーザー登録によって、クレジットの端末間共有とランキング名の設定を可能にする
- 外部IdPはGoogleから開始し、将来追加できるようにする
- 登録完了後は、登録開始前の画面と操作フローへ戻す

### 8.8 ランキングと結果

- プレイヤーの主要評価は、ゲームごとに定義されたスコア、勝敗、攻略結果とする
- 観客数や人気をゲーム結果の代替にしない
- ランキングはゲーム結果から生成する読み取りモデルとする
- ライブの名勝負・名プレイを発見する仕組みと、長期ランキングを分離する
- 匿名プレイヤーはシステム発行名で登録し、自由入力を許可しない
- 登録ユーザーはプロフィール名をランキング名として利用できる
- 登録直後は、自分の順位が見える位置を表示する

### 8.9 コメント・リアクション

- 観客同士が同じプレイを見ながら会話できる
- リアクションは、プレイ中の重要な瞬間へ簡単に反応できる形式とする
- プレイヤー画面へコメントを常時表示しない
- プレイヤーが希望する場合、プレイ終了後に反応を確認できる
- 荒らし、差別、嫌がらせ、ネタバレ、初心者への攻撃を抑止する通報・制限機能を持つ
- 未登録観客にも利用を認める場合は、投稿頻度、端末識別、NGワードなどの悪用対策を設ける

### 8.10 共有

- 筐体ごとに恒久的またはセッション有効期間中の共有URLを発行する
- プレイヤーと観客の双方が観戦URLを共有できる
- 共有先ではライブプレイを最初に表示する
- URLには必要に応じてゲーム名、プレイヤー名、サムネイル、ライブ状態を表すOGP情報を設定する
- プレイ終了後のURLでは、終了状態と次に観られるプレイまたは店内への導線を示す

## 9. ゲーム設置要件

### 9.1 選台方針

外部開発者が自由に無審査で公開する投稿市場にはしない。店の思想に合うゲームを運営が審査し、筐体として設置する。

設置するゲームは、原則として次を満たす。

- 遊んで面白い
- 観ても面白い
- 一人でやり込める
- 対戦または協力へ拡張できる、もしくは観戦に十分な挑戦性がある
- 数分から数十分で一回の区切りがつく
- 技術、判断、攻略が結果に反映される
- ハイスコア、勝負、協力などの見せ場がある
- 初見の観客が状況を理解する手掛かりを提供できる
- 課金で勝敗を有利にしない
- 初心者の挑戦意欲を不当に損なわない

### 9.2 開発者向け要件

- 開発者はゲームを掲載するのではなく、ゲームセンターへ筐体として設置する
- ゲームはプラットフォーム共通のプレイヤー、筐体、観戦、クレジット、結果、ランキングAPIへ接続できる
- ゲームごとに、プレイ人数、必要クレジット、結果形式、観戦情報、対戦・協力条件を宣言できる
- 観戦者が理解できる公開状態と、プレイヤーだけが持つ秘密情報を分離できる
- ゲーム更新は審査、バージョン管理、ロールバックを行える
- 権利者から許諾を得たレトロゲームも、将来同じ設置モデルで追加できる

## 10. 運営要件

### 10.1 店主・運営の責務

- 店の思想に沿ってゲームを選定する
- トップで紹介する筐体やイベントを編成する
- 初心者と熟練者の双方が挑戦できる環境を作る
- 不正プレイ、ランキング改ざん、迷惑行為を監視する
- コメント、プロフィール、共有内容への通報を処理する
- 障害時のクレジット返却とユーザー告知を行う
- ゲーム開発者と権利者の契約、収益分配、公開停止を管理する

### 10.2 必要な公開情報

- 利用規約
- プライバシーポリシー
- 特定商取引法に基づく表記
- 資金決済法などクレジット設計に応じた法的表示
- 問い合わせ先
- 通報窓口
- 対応ブラウザ・動作環境
- 障害・メンテナンス情報
- 返金・クレジット返却方針
- コミュニティガイドライン
- ゲームおよび素材の権利表記

### 10.3 SLO候補

- 店舗トップと観戦入口の可用性
- 観戦開始までの時間
- プレイヤーから観客への状態伝播遅延
- 途中参加時の状態復元時間
- クレジット消費・返却処理の成功率
- 決済完了からクレジット反映までの時間
- ゲーム結果登録の成功率

具体値は本番負荷試験と運用コストを確認して別途定義する。

## 11. 非機能要件

### 11.1 リアルタイム性

- 観戦者がプレイヤーと同じ重要な瞬間を共有できる遅延に抑える
- 弾やオブジェクトは決定的な初期情報から観戦側で補間・再現し、通信量を抑える
- 定期キーフレームで差分を補正する
- ボス撃破、ゲームオーバー、勝敗など重要イベントは欠落させない

### 11.2 性能とスケーラビリティ

- 筐体ごとにリアルタイムルームを分離する
- 観客数増加時もプレイヤーのゲーム進行へ影響を与えない
- 高頻度ゲーム状態を永続DBへ直接書き込まない
- 店舗、ゲーム、筐体を独立して増やせるモデルとする
- 盛り上がった一つの筐体へ観客が集中する負荷を想定する

### 11.3 セキュリティと不正対策

- クレジット残高、決済、ランキング結果をクライアントだけで確定しない
- 観戦者からのゲーム操作を拒否する
- セッション、OAuth、決済Webhook、共有URLを適切に検証する
- チート、改造クライアント、リプレイ送信、不正スコアを検知・隔離できるようにする
- 匿名利用を維持しながら、荒らしや多重特典取得を抑止する

### 11.4 プライバシー

- 観戦だけの利用者へ不要な個人情報登録を要求しない
- 規約同意は、ユーザー登録や有料クレジット購入など必要な時点で取得する
- Welcome Credit付与と規約同意を別の状態として管理する
- 観客の関係性や共有経路を盛り上がり判定へ使う場合、個人関係を公開せず集計情報として扱う
- プレイヤーはプロフィール名、観戦通知、コメント表示範囲を管理できる

### 11.5 アクセシビリティと端末対応

- PCとスマートフォンの双方で、店内探索、観戦、プレイ、共有を完結できる
- スマートフォンでは、観戦URLから一操作も要求せず映像領域を表示する
- タッチ操作中にゲーム終了画面のボタンが誤反応しないよう、終了演出と操作受付に時間差を設ける
- 色だけに依存せず、盛り上がり、状態、選択可否を伝える
- 音を使わなくても観客の気配とゲーム状況を理解できるようにする

## 12. 成功指標

### 12.1 北極星指標候補

**関係外の観客を含む、ライブプレイの有効観戦時間**

単なる総プレイ時間や課金額ではなく、本気のプレイが観客を集め、観客がその場に留まったことを測る。

### 12.2 主要指標

- 観戦URLを開いてライブ表示へ到達した割合
- 観戦開始までの時間
- 同時観戦者数と観戦者数の増加速度
- 共有URL経由の新規観戦者数
- 直接招待された観客から、関係の薄い観客へ広がった割合
- 観戦から初回プレイへ移った割合
- 無料プレイから有料クレジット購入へ移った割合
- プレイヤーが再訪し、同じゲームをやり込んだ回数
- 観客が別のライブプレイも観た割合
- プレイ終了後に再共有された割合
- 対戦・協力申込みと成立率
- 初心者の初回プレイ後継続率

### 12.3 避けるべき最適化

- 滞在時間を伸ばすためだけの無目的な周回
- 過剰な通知による再訪促進
- 観客数だけを求める扇情的な設計
- リアクション連打による盛り上がり順位操作
- 課金額による露出、勝敗、ランキング優遇
- 初心者を犠牲にした上級者向けの一方的な対戦

## 14. 現時点の非目標

- 歴代最高記録だけを称える静的なランキングサイト

## 15. 要件の要約

本サービスは、オンライン上にある一軒のゲームセンターである。ユーザーは登録せずに人だかりのできた筐体を覗き、今その場で起きている本気のプレイを観られる。面白いプレイは共有によって新しい観客を呼び、観客の中から次の挑戦者が生まれる。

クレジットは一回を大切にするために存在し、課金で勝敗を変えない。プレイヤーの価値はハイスコア、勝利、攻略によって決まり、観客はその挑戦を見届ける。店には、遊んでも観ても面白いゲームだけを運営が選んで設置する。

目指すのは、ゲームを消費させる場所ではない。

> 一回は濃く、関係は長く。  
> 本気のプレイが脈打ち、人が集まり、次の挑戦が生まれる場所。
