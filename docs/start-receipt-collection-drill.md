# 応答欠落の集計不能（コード10）通知・復旧訓練

対象は検証環境の監視Workerだけ。本番・main・ゲームの停止・長時間負荷試験は対象外。

## 安全境界

- 既存 `pulbase-service-monitor` の読み取り先を一時的に隔離D1 `pulbase-revocation-drill-20261020` へ切り替える。ゲームアプリWorkerのbindingや通常DBのスキーマ・レコードは変更しない。隔離D1にも書き込まない。
- 通常DBのbindingを残したまま、一時binding `START_SLO_DRILL_DB` と20分の有効期間を持つ変数だけを追加する。期間内は通常と同じ集計SQLが隔離D1の未作成テーブルで実際に失敗し、既存の例外処理がコード10を出す。故障値・件数・メールを直接作る訓練ではない。
- 開始前に既存通知値0、死活正常、最新の集計成功・鮮度、他の訓練マーカーなし、隔離D1に対象3テーブルがないことを読み取り確認する。既存障害がある場合は開始しない。
- 一時設定はstaging・固定Worker/アカウント/DB・固定dataset/KV/サービス・非公開URL・既存5分Cronを検証する。任意の宛先、時刻、SQLをコマンド引数で受け取らない。Secret・メール宛先・通知条件・ポリシー数を変えず、HTTP/RPCの故障操作口を追加しない。
- 20分の期限以降はコード自体が通常DBへ戻る。手動復元できなくても、永久に隔離D1を参照する設定にはしない。ただし最終的に基準設定を再デプロイし、一時bindingと変数を除く。自動期限の境界はローカル実D1/単体試験で検証する。
- `.wrangler/start-receipt-drill.json` に開始試行と期限だけを保存し、同じ作業場所から24時間以内の再開始を防ぐ。これはローカルの誤再試行防止であり、分散ロックや権限境界ではない。別の場所から並行開始しない。失敗時は記録・実状態を確認し、ファイルを消して自動再試行しない。

## 通知データ

自然5分Cronの `start-receipt-v1` に `start-receipt-d1-drill-v1` / `fault` のタグを付ける。期限で自動復帰した場合は同じタグに `expired`、基準設定の復元後はタグなしになる。D1の月間SLO台帳やゲーム要求を新しく作らず、監視の取得不能だけを再現する。

コード10の数値0の分母・欠落は取得不能時の形式であり、実測のゼロ件ではない。集計が正常に戻った場合も対象なしの0件をプレイ成功や月間SLO達成の証明にしない。通知は既存ポリシーの優先順に従い、より高い優先度の実障害があればそちらを先に対処する。

## 実施・復旧手順

`apps/web` から実行する。いずれも明示的なstaging指定が必要で、本番/宛先上書きは拒否する。

1. `node scripts/start-slo-drill.mjs --environment staging status` で現在値を確認する。
2. 全テスト・型検査・ビルド・監視Workerのdry-runが成功したら、`node scripts/start-slo-drill.mjs --environment staging fault` を1回だけ実行する。専用DBのスキーマ確認と開始条件の検証後に監視Workerだけを更新する。
3. 自然Cronの実データがタグ付きerror/コード10であること、通知SQLが10であること、通常の検証サイトが正常であることを確認する。手動scheduled・通知のテスト送信・閾値引下げは使わない。
4. 登録メールに届いた実メッセージの同一ポリシー、Trigger 10、評価時刻・メール日時を確認する。前回のコード9や遅延した再通知を混同しない。
5. `node scripts/start-slo-drill.mjs --environment staging restore` で基準設定へ戻す。このコマンドはAnalytics Engineやローカルの解析用トークンに依存せず、Wranglerの既存デプロイ認証だけで実行できる。取得不能でstatusに失敗しても復元を先に行える。
6. 新しい自然Cronがタグなしの通常D1集計/コード0となり、通知SQLも0、同じポリシーのResolvedメールが届いたことを確認する。基準設定の再デプロイ出力で一時binding・変数がないことを確認する。データや過去のエラー記録を消して解除しない。

## 検証範囲・残課題

これは読み取り先/スキーマ不整合による集計不能と、自然通知・通常DBへの復帰の訓練である。Cloudflare D1全体の停止、資格情報失効、AE配送停止、監視Cron停止・記録陳腐化、複数障害の独立通知、一般利用者のゲームの復旧までを合格扱いにはしない。コード10の欠測・陳腐化分岐は既存の読み取り専用SQL試験と区別する。
