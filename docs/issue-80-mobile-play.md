# Issue #80: スマートフォンのプレイ表示

共通 GameScreen の「観戦に招待」を game-frame の直後に移動した。共有処理は既存のまま使用する。

幅820px以下、または粗いポインターを持つ端末で、プレイヤーの状態が playing になると画面内をゲームと操作ボタンで占有する。Fullscreen API は呼ばず、iPhoneを含め同じCSS方式で表示する。ブラウザのアドレスバー等はOS・ブラウザ側の表示として残る。

ランキング等を隠し、通常ページを inert にして、スクロール・文字選択・コンテキストメニューを抑止する。canvas の入力イベントはゲーム固有の処理へ渡す。セーフエリアと動的ビューポートの高さを使い、ゲーム画像は縦横比を維持して収める。「通常表示に戻る」または Escape で解除し、終了・退出・アンマウントでも元のスクロール位置と操作を復元する。明示的に解除したプレイでは、再開だけで自動的に全画面へ戻さない。「全画面でプレイ」で再度切り替えられる。

適用先は共通 GameScreen を使用する BUZZ BARRIER（graze-duel）と DEEP SEA SALVAGE。DOT WAVE は独立した React 画面を使用し、この共通UI変更の対象外。PCの通常ポインター環境と観戦状態では自動切り替えしない。

## PR #85 独立レビューへの追加修正

- BUZZ BARRIERの実WebGLレンダラーのobject-fitをCSS変数で切り替え、全画面では基底canvasと同じcontainにする。通常表示のcoverは維持する。両描画レイヤーは同じ960×640と中央配置を使用する。
- DEEP SEA SALVAGEはcontainの余白とcoverの切り抜きを差し引いて入力をゲーム座標へ変換する。余白からの操作開始は無視し、ドラッグ中の領域外座標は画像端へ制限する。pointercancelでも入力を解除する。
- ブラウザケースには実WebGLレンダラーの弾ピクセル・基底画像との表示変換の一致と、深海ゲームの実入力変換・シミュレーション・2Dレンダラーによるドラッグ移動の検証を追加した。両ゲームの390×844と844×390でプレイ中画像を添付する。共有ストアのみの表示テストに加えた描画・入力単体のケースであり、認証を伴うゲーム開始の受け入れ確認は別途必要。

今回のsandboxでは座標変換6ケースと余白入力拒否のNode直接実行、ブラウザspec構文確認、git diff --checkが成功。集中Vitestとnpm testはlisten EPERM 127.0.0.1で起動失敗。初回buildの新規テストの型エラーを修正後、npm run build:stagingは成功（既存のチャンクサイズ警告あり）。ローカル待受制限のためブラウザケースは未実行で、画像は独立CI実行時に生成する。実機・デプロイ・検証公開先のSHA照合・Issueコメントは未実施。これらのマージ後受け入れ条件は未確認のまま維持する。

## 解析パネルとBUZZ BARRIER実入力の追加修正

全画面の重なり順を2200にし、通常ページの解析設定パネル（2100）がゲームや解除操作を覆わないようにした。通常表示のパネル順位・同意状態・保存処理は変更していない。未選択パネルを残した縦390×844・横844×390のブラウザケースで、解除ボタンのヒット対象と通常クリック、解除後の未選択表示・パネル操作の復元を検査する。

BUZZ BARRIERの実描画ケースに既存のcreateInputControllerと実シミュレーションのmovePlayerを接続した。compactはfalseとして全画面DOMによるドラッグ許可を通し、縦横それぞれで両軸の移動・pointerup後の停止・入力破棄後の停止を検査する。移動後の画像を既存の添付処理で保存する。入力JSの変更はない。
