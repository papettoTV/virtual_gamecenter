# Issue #80: スマートフォンのプレイ表示

共通 GameScreen の「観戦に招待」を game-frame の直後に移動した。共有処理は既存のまま使用する。

幅820px以下、または粗いポインターを持つ端末で、プレイヤーの状態が playing になると画面内をゲームと操作ボタンで占有する。Fullscreen API は呼ばず、iPhoneを含め同じCSS方式で表示する。ブラウザのアドレスバー等はOS・ブラウザ側の表示として残る。

ランキング等を隠し、通常ページを inert にして、スクロール・文字選択・コンテキストメニューを抑止する。canvas の入力イベントは変更しない。セーフエリアと動的ビューポートの高さを使い、ゲーム画像は縦横比を維持して収める。「通常表示に戻る」または Escape で解除し、終了・退出・アンマウントでも元のスクロール位置と操作を復元する。明示的に解除したプレイでは、再開だけで自動的に全画面へ戻さない。「全画面でプレイ」で再度切り替えられる。

適用先は共通 GameScreen を使用する BUZZ BARRIER（graze-duel）と DEEP SEA SALVAGE。DOT WAVE は独立した React 画面を使用し、この共通UI変更の対象外。PCの通常ポインター環境と観戦状態では自動切り替えしない。

## マージ前の検証

- `node --test tests/spectator-ui-layout.test.mjs`: 成功。
- `tsc --noEmit`: 成功。
- `npm run build:staging`: 成功。大きいチャンクの既存警告あり。
- 共有の集中テストと `npm test`: sandbox の `listen EPERM 127.0.0.1` により実行環境の起動に失敗。テスト合格とは扱わない。
- `tests/ui/mobile-play.spec.mjs`: 独立Web checks用のブラウザケースを追加。390×844・412×915、横向きへのリサイズ、招待パネル、選択・メニュー抑止、ホイール、解除・終了・退出の復元、PC・観戦を検証する。実認証・クレジット・開始APIを置換せず、実コンポーネントと共有ストアを使用する表示単体のケース。sandboxではローカル待受不可のためブラウザ実行は未実施。

## マージ後に残る受け入れ確認

検証公開・SHA照合・Issueへの証跡記録はこの実装では未実施。人によるstaging承認後に、iPhone SafariとAndroid Chromeで実際にゲーム開始し、移動・スワイプ・長押し、回転、ノッチ周辺、終了・退出後のスクロール、招待URL、PC操作と観戦を確認する。ブラウザケースだけではゲーム固有のタッチ操作や実端末の挙動の合格を保証しない。未確認項目が残る間はIssueをopenとする。
