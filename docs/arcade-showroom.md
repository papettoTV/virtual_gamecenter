# トップページ：ゲームを眺めて回るショールーム

## 体験

- ゲーム映像を入口にし、タイトルを知らなくても気軽に見て回れる構成。
- PC は左に映像、右にゲーム名・説明と観戦／プレイへの導線。
- スマホは一列。映像、短い説明、操作ボタンの順で縦スクロールする。
- ゲームカタログの登録順（BUZZ BARRIER → DOT WAVE → 深海サルベージ）に表示し、4番目は同じカード構成の Coming Soon。
- ロゴの下に読み方「パルベース」を添える。タグライン「本気のプレイが、人を呼ぶ。」は独立して維持する。
- 架空のゲーム映像や観客は表示しない。デザイン検討画像は本番素材として使わない。

## 映像と筐体

- 10秒ごとに既存の筐体一覧 API を取得する。非表示タブでは取得しない。
- プレイ中の筐体があれば LIVE、なければ DEMO。観戦者数が多い筐体を代表として選ぶ。
- 既存の観戦画面を同一オリジン iframe で表示する。必ず `watch=1` で接続し、着席・クレジット消費はしない。
- プレビューは固定960×640の表示領域を縮小し、スマホでもゲーム内座標を変えない。
- 実際の観戦者数を表示する。トップ内プレビューの接続も既存サーバーでは観戦接続として数える。
- プレイ中筐体は四角い点で全件表示する。観戦者3人以上は赤、それ以外は緑。点を選ぶとその筐体へ直接観戦に移る。
- 映像は表示専用とし、タップ／クリックでは遷移しない。「遊ぶ」ボタンから筐体選択を挟まず開始確認へ進む。観戦は「観戦する」ボタンまたはプレイ中筐体の点から選ぶ。
- トップの背景は暗いゲームセンターの間接照明画像を使い、各ゲームの枠はシアン〜紫の細いグラデーションと静的な発光で表現する。映像・文言・構成はそのまま維持する。背景と発光はトップだけに適用し、クリックを遮らず、追加のアニメーションも行わない。
- 映像と説明の境界は外枠に馴染む青〜紫の細いグラデーション線で区切る。PCでは縦線、スマホの縦積みでは横線にする。境界線には強い発光を付けない。
- Coming Soonは左右分割せず、カード幅いっぱいの横長パネルとする。中央の見出し・細い光のアクセント・案内文と、両端の控えめなドット模様で表現する。
- 背景素材は `apps/web/public/assets/showroom/arcade-ambient-v1.jpg` に保存。生成情報は同ディレクトリの `arcade-ambient-v1.json` に記録する。
- 観戦ボタンは常に表示する。プレイ中の筐体がない場合はグレーアウトして無効にする。

## デモと負荷

- BUZZ BARRIER と DOT WAVE は既存の実プレイ動画をミュート・ループ再生する。
- BUZZ BARRIER は「宣伝素材」で撮影した現行のワイヤーフレーム型ボスの映像を使用。`apps/web/public/demos/buzz-barrier/boss-demo-v1.mp4` とポスター・出典JSONを保存。元動画を再圧縮せずコピーし、現行 `boss-geometry.ts` とのSHA256一致を確認済み。
- デモを更新するときはバージョン付きの新しいファイルを保存し、出典・撮影条件・コード版・ハッシュを記録してからゲームカタログの参照先を変更する。既存の撮影元は削除しない。
- 深海サルベージは既存のシミュレーションと2D描画を使った自動操作デモ。実プレイ・予約・ランキング登録は行わない。
- 画面外／非表示タブではライブ iframe を外して接続を閉じ、動画を停止し、デモの描画ループを破棄する。
- プレビュー用の規約・プロフィール・共有 UI は表示しない。アクセス解析は既存の iframe 除外に従い、観戦流入イベントもプレビューでは記録しない。
- ライブ映像は既存の観戦ランタイム全体を再利用する初期実装。今後ゲーム数が増える場合は専用の軽量プレビューレンダラーへの切り出しを検討する。

## 確認項目

- PCの左右表示／375px幅の縦表示と、横はみ出しのないスクロール。
- 各ゲームの実デモ、ライブ表示への切替、映像と筐体の点から観戦への遷移。
- プレイボタンから筐体選択を挟まない開始確認・READYへの遷移。
- 画面外の動画停止／iframe削除、タブ非表示時の停止。
- カタログ変更への追従、規約・プロフィール・フッターは従来の導線を維持。

## 筐体選択画面の省略

- トップの「遊ぶ」・デモ選択は新しい筐体URLへ進み、クレジット消費前に開始確認を表示する。トップを押した時点では消費しない。
- BUZZ BARRIER と深海サルベージは共通の開始確認後、従来のREADY／潜航開始待ちへ進む。DOT WAVEは既存の開始パネルを「ゲームを開始しますか？」の確認として使い、確定後にカウントダウンする。課金・予約処理は従来どおり。
- 開始確認のキャンセル／残高不足画面のクローズはトップへ戻す。DOT WAVEのキャンセルをSpaceで操作しても開始ショートカットを実行しない。
- 共通の「遊び方」はクリックするとモーダル表示し、Esc・モーダル外のタップ・閉じるボタンで閉じる。操作とコツはゲームカタログで管理し、タッチ操作端末にはスマホ用説明を表示する。
- 遊び方の項目は全ゲームで「目的・操作・遊び方・終了条件・コツ」に統一し、見出し付きの表で表示する。
- プレイ中の「別のゲームをする」は、終了すると使用済みクレジットが戻らないことを確認する。キャンセル時はゲーム画面に留まり、観戦中・結果画面・未課金の開始前には確認を出さない。
- 旧 `/?game=...` のリンクも新規開始確認へ置き換える。ブラウザの戻る操作で旧リンクにループしないよう履歴は置換する。
- 観戦URLは維持。`watch=1` の接続は、同じユーザーのブラウザでもプレイヤー席を再取得しない。
- 退席済み・未着席の観戦URLには「自分も遊ぶ」「ほかのゲームを見る」を表示。追加のAPIポーリングやWebSocketは使わず、既存ソケットの在席通知で切り替える。プレイヤーが残っているゲーム終了・リザルト時は観戦表示を維持する。
- 「自分も遊ぶ」は観戦していた筐体を奪わず新規筐体へ進む。同じゲーム内でも筐体URLや観戦モードが変わればランタイムを再初期化する。
- 観戦画面の戻り先もトップへ変更。旧筐体選択の大きなUIと重複デモは撤去し、待機時に必要な案内と内部連携用要素のみ残す。
- DOT WAVEで開始画面を覆っていた重複共有オーバーレイを撤去。画面上部の共有ボタンは維持する。
