# Issue #167: 429復帰テストの待機時間

対象は `read-budget.spec.mjs` の残高更新と、`play-confirmation.spec.mjs` の登録キャンセル後の復帰2件・観戦終了1件。模擬429の待機を60秒から6秒へ変更する。5秒を超える非同期復帰の検査は維持する。

プローブごとにローカル専用IPv6識別子を作り、対象GETの初回と再試行に同じ `CF-Connecting-IP` を渡す。接続先は既存のローカルURL検査で限定する。Cookie、ゲスト、プレイヤー単位の制限、Workerの実レスポンスと残高は維持する。遅延付きDOT WAVE観戦ケースでは、プレイヤーと観戦者それぞれのbootstrap/credits GETも、セットアップから復帰後までコンテキスト別の固定IPで分離する。書込には上書きを適用しない。実429の場合はWorkerのRetry-Afterをそのまま尊重する。

別途、専用のローカルゲストで実際のbootstrap枠を消費し、実429のRetry-After以上待って1回だけ再試行し、実残高へ復帰するブラウザケースを追加した。このケースの待機時間もUIステップ全体の比較に含める。
