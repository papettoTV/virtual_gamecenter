# 自動実装でのPNG/JPEG素材追加

自動実装はテキスト差分と `assets` 配列を返す。画像バイト・base64・Git binary patchをテキスト差分に埋め込まない。素材だけなら `patch` は空文字でよい。素材がなければ `assets: []` とする。

```json
{"summary":"共有画像を登録しました","patch":"","assets":[{"path":"apps/web/public/share/game-v1.jpg","url":"https://github.com/user-attachments/assets/00000000-1111-2222-3333-444444444444","sha256":"取得する原本のSHA-256（64桁の小文字16進数）"}]}
```

実装エージェントは外部APIへ接続しない。認証を持つ公開ジョブが信頼された固定コードで取得し、候補コードは実行しない。素材取得リクエストへGitHub Appの認証は送らない。

- 保存先は `apps/web/public/` 配下の `.png`、`.jpg`、`.jpeg`。パスの各要素は英数字・ハイフン・アンダースコアのみ。
- GitHubの添付URLと、そのリダイレクト先の固定S3ホストだけを許可。任意URL、URLへの認証情報、リダイレクトの連鎖は拒否する。添付のContent-Typeだけを信用せず、実データと保存先拡張子の形式を照合する。
- PNGはシグネチャ・チャンクCRC・IHDR・静的/非インターレース形式・展開長と行フィルターを検査。JPEGは8bit baseline/progressiveのマーカー構造、寸法、走査データの区切り、終端を検査する。JPEGの画素デコード全体を実行した検査ではない。
- 各画像2MiB以下、最大8枚・合計8MiB、幅/高さ4096以下・1600万画素以下。PNG展開後は64MiB以下。承認されたSHA-256と一致する原本だけを登録する。
- シンボリックリンク・実行可能ファイル・拡張子偽装・画像をテキストパッチで追加する方法は拒否する。親ディレクトリのリンクも拒否する。
- 画像を含むPRも独立レビュー・同じ候補SHAのCI・develop自動マージを経る。公開処理の権限、ci-control保護、strict、本番ブランチ保護、staging承認1回は変更しない。

## Issue #90

添付3枚はURL/Content-Typeとファイル名がPNGだが、実データはJPEG。ユーザー指示によりPNG/JPEG両対応とし、原本の寸法1200×630・内容・SHA-256を維持して `.jpg` に保存する。新規画像生成・再圧縮・変換はしない。SNSクローラーのために検証用Basic認証を解除しない。

この対応はアプリ用画像に限る。CI/CD・公開先・鍵・認証設定を画像や別の許可パスへ隠して変更することは許可しない。保護コードの変更は人がci-controlへ配置し、bypassを空へ戻して固定SHA/設定版を照合した後に有効になる。
