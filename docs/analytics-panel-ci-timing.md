# アクセス解析設定テストの操作整理（Issue #175）

## 幅ごとの確認項目

`analytics-panel.spec.mjs` はdesktop/mobileそれぞれ4ケースのまま維持する。CIの分割構成・製品コードは変更しない。

| 幅 | desktop | mobile |
| --- | --- | --- |
| 1280×800 | 初期固定・横はみ出し・auto/smoothスクロール・全ボタン到達、保存と再表示の一連操作 | 初期固定・横はみ出し・autoスクロール・全ボタン到達 |
| 390×664 | 初期固定・横はみ出し・autoスクロール・全ボタン到達 | 初期固定・横はみ出し・autoスクロール・全ボタン到達、保存と再表示の一連操作 |
| 320×568 | 初期固定・横はみ出し・autoスクロール・全ボタン到達 | 同左 |
| 568×240 | 本文・全ボタンのスクロール到達、試行クリック、画像、閉じる | 同左 |

保存と再表示の一連操作は、閉じる→フッターから未選択で再表示→拒否を保存→再読込→フッターから拒否状態で再表示→同意を保存→再読込→フッターから同意状態で再表示。拒否・同意の両方で検証環境の案内も検査する。代表幅の操作を`test.step`で区切り、レポートで時間を追えるようにする。

CSSの720px以下は縦配置、それより広い幅は横配置。代表幅はPCの横配置1280px、スマホの縦配置390pxとする。保存・再表示の処理には幅による分岐がない。320pxの折り返しと568×240pxの内部スクロールは幾何検査・操作到達検査を維持する。通常3幅の全ボタンはviewport内確認に加えて試行クリックでも到達を確認する。

一連操作は両project合計6回から2回、再読込は12回から4回、フッター経由の再表示は18回から6回になる。全幅のautoスクロールとdesktop 1280pxのsmoothスクロールは削減しない。連続フレームの幾何情報、失敗時の画像、低い画面の本文・ボタン画像の収集も維持する。
